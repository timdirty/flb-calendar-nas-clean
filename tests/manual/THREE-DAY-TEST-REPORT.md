## 🔍 問題深度分析

### 快取同步問題

**問題表現**：
```javascript
// 第一次操作成功
POST /api/events/mark-special → 200 OK

// 延遲 1 秒

// 第二次操作失敗
POST /api/events/mark-special → 400 Bad Request
Error: "事件快取未就緒，請稍後再試"
```

**根本原因**：
1. **快取更新異步**：`server.js` 在更新事件後，可能需要時間同步快取
2. **CalDAV 延遲**：Synology Calendar API 可能有延遲
3. **快取策略**：快取可能在某些操作後被清空，需要重新載入

**受影響的功能**：
- ❌ 連續多次標記操作
- ❌ 增量/替換模式切換
- ❌ 部分移除標記
- ❌ 描述保留完整性測試（最關鍵）

## 💡 解決方案建議

### 短期解決方案（立即可行）

1. **增加延遲時間**
   ```javascript
   // 當前：1000ms
   await delay(1000);
   
   // 建議：2000-3000ms
   await delay(3000);
   ```

2. **添加重試機制**
   ```javascript
   async function retryOperation(fn, maxRetries = 3) {
     for (let i = 0; i < maxRetries; i++) {
       try {
         return await fn();
       } catch (error) {
         if (i === maxRetries - 1) throw error;
         await delay(2000);
       }
     }
   }
   ```

3. **手動刷新快取**
   ```javascript
   // 在每次操作後調用
   await makeRequest('GET', '/api/events/refresh-cache');
   ```

### 中期解決方案（需要修改後端）

1. **優化快取更新機制**
   - 同步更新快取，而非異步
   - 在 API 返回前確保快取已更新

2. **添加快取狀態檢查**
   ```javascript
   // 新增 API
   GET /api/events/cache-status
   Response: { ready: true, lastUpdate: timestamp }
   ```

3. **實作樂觀更新**
   - 立即更新本地快取
   - 背景同步 CalDAV

### 長期解決方案（架構優化）

1. **引入事件驅動架構**
   - 使用事件總線通知快取更新
   - WebSocket 推送更新給前端

2. **改用資料庫**
   - 替代純快取方案
   - 提供即時一致性保證

3. **分離讀寫**
   - 寫入操作直接更新資料庫
   - 讀取操作從快取獲取
