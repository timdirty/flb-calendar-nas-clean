# 特殊事件專用 Flex Message 範本實作計劃

## 背景

目前系統使用動態變數 `{headerColor}` 和 `{specialEventBadge}` 來處理特殊事件，但這導致系統不穩定。需要改為創建 12 個獨立範本，每個範本 hardcode 對應的顏色和徽章。

## 實作步驟

### 1. 在 `flex-message-templates.json` 的 `templates` 區塊中新增 12 個範本

#### 停課範本（紅色 #dc3545）

- `todayCancelled`: 標題「⚠️ 停課通知 - 當日課程」，徽章「🔴 停課」
- `tomorrowCancelled`: 標題「⚠️ 停課通知 - 明日課程」，徽章「🔴 停課」
- `beforeClassCancelled`: 標題「⚠️ 停課通知 - 課前提醒」，徽章「🔴 停課」

#### 體驗範本（金色 #FFD700）

- `tomorrowExperience`: 標題「⭐ 體驗課通知 - 明日課程」，徽章「🟢 體驗」
- `beforeClassExperience`: 標題「⭐ 體驗課通知 - 課前提醒」，徽章「🟢 體驗」

### 2. 範本結構說明

每個特殊事件範本基於對應的基礎範本（today/tomorrow/beforeClass），修改以下部分：

**header 區塊修改**：

- `backgroundColor`: 從 `{headerColor}` 改為 hardcode 顏色
- `text`: 修改為特殊事件專屬標題

**body 課程名稱區塊修改**：

- specialEventBadge text 元素的 `text`: 從 `{specialEventBadge}` 改為 hardcode 文字
- specialEventBadge text 元素的 `backgroundColor`: 從 `{specialEventColor}` 改為 hardcode 顏色

**beforeClass 範本額外修改**：

- body 第一個 text（"即將開始上課！"）的 `color`: 從 `{headerColor}` 改為 hardcode 顏色

### 4. 修改 notification-manager.js

更新 `buildFlexMessage()` 函數的模板類型映射邏輯：

- 偵測到特殊事件時，組合範本名稱（例如：`today` + `Cancelled` = `todayCancelled`）
- 優先使用特殊事件範本，若不存在則降級為普通範本
- 移除或簡化 headerColor 和 specialEventBadge 的動態賦值邏輯

**關鍵修改位置**（notification-manager.js line 407-481）：

```javascript
buildFlexMessage(templateType, variables) {
  // ... 現有的特殊事件偵測邏輯 ...
  
  // 如果偵測到特殊事件，優先使用專用範本
  if (specialEventType) {
    const specialTemplateMap = {
      '停課': 'Cancelled',
      '體驗': 'Experience', 
      '代課': 'Substitute',
      '改時間': 'TimeChange'
    };
    const suffix = specialTemplateMap[specialEventType];
    const specialTemplateName = `${mappedType}${suffix}`;
    
    if (this.flexTemplates.templates[specialTemplateName]) {
      // 使用特殊事件專用範本
      const template = this.flexTemplates.templates[specialTemplateName];
      const flexMessage = JSON.parse(JSON.stringify(template));
      let result = this.replaceFlexVariables(flexMessage, variables);
      result = this.cleanFlexMessage(result);
      return result;
    }
  }
  
  // 降級：使用普通範本（保持現有邏輯）
  // ...
}
```
