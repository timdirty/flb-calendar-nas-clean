# 視圖切換與學習歷程上傳系統優化

## 問題分析

### 視圖切換問題

1. **重複觸發自動綁定**：每次切換視圖時會重新檢查並執行講師自動綁定流程
2. **頁面重新載入**：視圖切換導致整個畫面刷新
3. **重複 API 調用**：切換視圖時重複呼叫後端 API，造成卡頓

### 學習歷程按鈕位置

- 目前按鈕在「課程已結束」文字的同一容器內
- 需要移到倒數計時器下方，作為獨立區塊

## 修復方案

### 1. 防止視圖切換重複觸發綁定

**檔案**：`public/perfect-calendar-optimized-complete2.html`

**修改位置**：

- `handleViewButtonClick()` 函數（約12290行）
- `switchView()` 函數（約12493行）
- `renderEvents()` 函數（約12605行）
- `processEventsData()` 函數（約11700行）

**修改內容**：

1. 在 `handleViewButtonClick()` 中添加防抖機制，防止快速連續點擊
2. 在 `switchView()` 中添加視圖切換標記 `window.isViewSwitching = true`
3. 修改 `processEventsData()` 中的自動綁定邏輯，當 `window.isViewSwitching` 為 true 時跳過
4. 添加全局標記 `window.initialBindingComplete` 標記初次綁定完成
5. 在所有可能觸發自動綁定的地方檢查這些標記

### 2. 優化 renderEvents 避免重複渲染

**修改位置**：`renderEvents()` 函數（約12605行）

**修改內容**：

1. 添加渲染防抖，避免短時間內重複渲染
2. 比較前後事件列表，如果完全相同則跳過渲染
3. 只更新變化的課程卡片，而非全部重繪

### 3. 優化 API 調用機制

**修改內容**：

1. 在視圖切換時使用已載入的 `allEvents` 數據，不重新調用 API
2. 添加 API 調用節流機制，防止短時間內重複請求
3. 確認 `apiOptimizer` 的快取機制正常運作

### 4. 調整學習歷程按鈕位置

**修改位置**：`updateAllCountdowns()` 函數（約8983行）和 CSS 樣式（約2852行）

**修改內容**：

1. 修改 `updateAllCountdowns()` 函數中的 HTML 結構
2. 將「課程已結束」文字和按鈕分離為兩個區塊
3. 調整 CSS 樣式 `.countdown-timer.overdue.clickable-upload`
4. 添加按鈕獨立樣式，確保視覺層次清晰

**新結構**：

```html
<div class="countdown-timer overdue">
    <i class="icon"></i>
    <span>課程已結束</span>
</div>
<button class="upload-learning-btn">
    <i class="fas fa-book-open"></i> 上傳學習歷程
</button>
```

### 5. 完善學習歷程上傳頁面

**檔案**：`public/learning-record-upload.html`

**檢查和確認**：

1. 頁面載入時自動顯示今日或本週已結束的課程
2. 未結束的課程顯示「課程尚未結束，無法上傳」提示
3. 上傳表單包含：

   - 每位學生：3 張照片 + 1 個影片 + 20 字評語的輸入欄位

4. 表單驗證邏輯完整
5. 從行事曆頁面跳轉時能正確定位到指定課程

## 關鍵修改點

### 防止重複綁定的標記系統

```javascript
// 全局標記
window.hasAutoBindedOnce = false;        // 已執行過初次自動綁定
window.userHasManuallySelectedInstructor = false; // 用戶已手動選擇
window.isViewSwitching = false;          // 正在切換視圖
window.initialBindingComplete = false;   // 初次綁定流程完成
```

### 視圖切換流程優化

```javascript
handleViewButtonClick() 
  → 設置 isViewSwitching = true
  → switchView() (只更新視圖變數)
  → updateStats() (只計算統計)
  → renderEvents() (使用現有資料渲染，不呼叫 API)
  → 設置 isViewSwitching = false
```
