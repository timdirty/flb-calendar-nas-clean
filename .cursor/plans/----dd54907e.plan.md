# 企業級流式上傳系統 - 完整實施計劃

## 問題根因分析

### 1. 影片崩潰原因

- **選擇階段**：即使影片不創建 video 元素，但檔案分類驗證時會讀取檔案元數據，觸發記憶體尖峰
- **預覽階段**：照片立即創建大量 Blob URL（Line 10610），iPhone LINE 內建瀏覽器記憶體限制嚴格（~100-150MB）
- **批次處理**：雖然延遲創建預覽，但所有檔案資訊已載入記憶體

### 2. 照片動畫不統一

- `.thumb-loading`：旋轉 spinner（learning-records.css Line 938-945）
- `.file-uploading-overlay`：半透明遮罩
- 多個 class 狀態切換（`.new-upload`, `.uploading`, `.loading`, `.loaded`）

### 3. 流式上傳未完全實現

- 壓縮階段仍等待預覽生成完成
- 預覽生成阻塞上傳開始
- 未實現真正的「選擇後立即上傳」

### 階段 2：流式優化

#### 2.1 創建流式上傳模組

**新增檔案**：`public/js/modules/learning-upload/streaming-uploader.js`

**核心功能**：

1. **檔案選擇後立即開始上傳第一個檔案**
2. **邊上傳邊壓縮後續檔案**
3. **背景生成預覽（不阻塞上傳）**
4. **實時記憶體監控與自動清理**

**關鍵實現**：

```javascript
async function startStreamingUpload(classifiedFiles) {
  console.log('🚀 [流式上傳] 開始');
  
  // 分離照片和影片
  var images = classifiedFiles.filter(f => f.isImage);
  var videos = classifiedFiles.filter(f => f.isVideo);
  
  // 立即開始上傳第一個檔案（不等待壓縮）
  var firstFile = images[0] || videos[0];
  if (firstFile) {
    // 快速壓縮第一個檔案
    var compressed = await compressImageIfNeeded(firstFile.file);
    uploadOne('image', compressed, 0, true, 0); // 立即上傳
  }
  
  // 背景處理剩餘檔案
  processRemainingFilesInBackground(images.slice(1), videos);
}
```

#### 2.2 惰性預覽載入器

**新增檔案**：`public/js/modules/learning-upload/lazy-preview-loader.js`

**功能**：

- 使用 Intersection Observer 監控預覽可見性
- 僅載入可視區域 ±2 個預覽
- 離開可視區域自動釋放 Blob URL

**實現**：

```javascript
var observer = new IntersectionObserver(function(entries) {
  entries.forEach(function(entry) {
    if (entry.isIntersecting) {
      loadPreview(entry.target);
    } else {
      unloadPreview(entry.target);
    }
  });
}, { rootMargin: '200px' });
```

## 新增輔助函數

### createProgressRing()

**位置**：`public/js/pages/learning-record-upload.js` 開頭

```javascript
function createProgressRing() {
  var container = document.createElement('div');
  container.className = 'upload-progress-ring';
  
  var svg = document.createElementNS('http://www.w3.org/2000/svg', 'svg');
  svg.setAttribute('width', '50');
  svg.setAttribute('height', '50');
  
  var circle = document.createElementNS('http://www.w3.org/2000/svg', 'circle');
  circle.setAttribute('cx', '25');
  circle.setAttribute('cy', '25');
  circle.setAttribute('r', '20');
  circle.setAttribute('fill', 'none');
  circle.setAttribute('stroke', '#60a5fa');
  circle.setAttribute('stroke-width', '3');
  circle.setAttribute('stroke-dasharray', '125.6');
  circle.setAttribute('stroke-dashoffset', '125.6');
  circle.setAttribute('transform', 'rotate(-90 25 25)');
  
  svg.appendChild(circle);
  container.appendChild(svg);
  
  var text = document.createElement('div');
  text.className = 'upload-progress-text';
  text.textContent = '0%';
  container.appendChild(text);
  
  return container;
}
```

### updateProgressRing(previewElement, percent)

```javascript
function updateProgressRing(previewElement, percent) {
  var circle = previewElement.querySelector('.upload-progress-ring circle');
  var text = previewElement.querySelector('.upload-progress-text');
  
  if (circle) {
    var offset = 125.6 - (125.6 * percent / 100);
    circle.setAttribute('stroke-dashoffset', offset.toString());
  }
  
  if (text) {
    text.textContent = percent + '%';
  }
}
```

## 測試計劃

### 基礎測試

1. 選擇 1 個影片（50MB）→ 應 < 0.5s 開始上傳
2. 選擇 5 張照片 → 檢查進度環統一
3. 選擇 10 張照片 + 5 個影片 → 檢查記憶體穩定

### 壓力測試

1. 選擇 20 個影片（各 50-100MB）→ 應不崩潰
2. 選擇 1 個超大影片（200MB+）→ 自動分片上傳
3. 弱網環境（3G）→ 檢查上傳穩定性

### 邊界測試

1. 選擇後立即切換課程 → 檢查上傳中斷處理
2. 上傳中關閉 LIFF → 再次開啟檢查狀態
3. 記憶體不足情境 → 檢查自動降級

## 風險與應對

### 風險 1：LIFF WebView 記憶體限制

- **應對**：嚴格的記憶體監控 + 自動降級策略（單檔案上傳）

- **應對**：自動回退到傳統上傳 + 用戶友好提示

### 風險 3：網路不穩定

- **應對**：失敗自動重試（最多 3 次）+ 斷點續傳
