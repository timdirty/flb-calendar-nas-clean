3. **前端未防快取**: 前端 `fetch()` 請求沒有加上 `no-cache` 設定

## 📋 HTTP Headers 說明

### 後端設定的 Headers
```http
Cache-Control: no-store, no-cache, must-revalidate, private
Pragma: no-cache
Expires: 0
```

**作用**:
- `no-store`: 不要儲存任何快取
- `no-cache`: 必須向伺服器驗證
- `must-revalidate`: 過期後必須重新驗證
- `private`: 只允許瀏覽器快取（不允許代理伺服器快取）
- `Pragma: no-cache`: 支援舊版 HTTP/1.0
- `Expires: 0`: 立即過期

### 前端設定的選項
```javascript
{
    cache: 'no-cache',  // Fetch API 選項
    headers: {
        'Cache-Control': 'no-cache',
        'Pragma': 'no-cache'
    }
}
```

## 🔍 技術細節

### 為什麼需要雙重防護？

**後端設定 Cache-Control**:
- 控制瀏覽器和代理伺服器的快取行為
- 確保 HTTP 層面不快取

**前端設定 cache: 'no-cache'**:
- 控制 Fetch API 的快取策略
- 確保 JavaScript 層面不快取
- 防禦性編程（萬一後端 header 被忽略）

### 為什麼要攔截靜態檔案請求？

```javascript
// 這個路由必須在 express.static() 之前
app.get('/student_data.json', ...);
app.use(express.static(...));
```

**原因**:
- Express 按順序處理路由
- 先匹配到的路由會優先執行
- 如果放在 `express.static()` 之後，靜態檔案中介軟體會先處理，我們的路由永遠不會執行

## 🎓 學習重點

### HTTP 快取機制
1. **瀏覽器快取**: 減少網路請求，提升效能
2. **Cache-Control**: 控制快取行為的標準 header
3. **即時性 vs 效能**: 需要權衡取捨

### Express 路由順序
1. 路由按定義順序執行
2. 先定義的路由優先匹配
3. `express.static()` 也是一個中介軟體

### Fetch API
1. `cache` 選項控制快取策略
2. 可以在 `headers` 中設定快取相關 header
3. 雙重防護確保可靠性
