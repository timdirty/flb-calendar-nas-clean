# 📋 學生簽到無法保存問題 - 完整報告

## 🔍 問題分析

### 1. 症狀
- 學生簽到後，重新打開頁面，所有學生恢復為「待簽到」狀態
- 簽到資料沒有正確保存到 `student_data.json`

### 2. 根本原因
**檔案權限問題！**

```
主機檔案權限：-rw-r--r-- 1 ctctim14 users
容器內顯示：  -rw-r--r-- 1 1026     users
Docker 進程：  運行為 nextjs 用戶（UID 1001）
```

**問題：** nextjs 用戶（UID 1001）無法寫入由 ctctim14（UID 1026）擁有的檔案

### 3. 錯誤日誌
```
❌ [自動更新] 更新學生資料失敗: EACCES: permission denied, open '/app/public/student_data.json'
```

## 📂 檔案路徑確認

### 正確的檔案位置
- **主機路徑**：`/volume1/homes/ctctim14/樂程坊計畫/課程資料/Cursor/講師行事曆檢視/flb-calendar-nas/public/student_data.json`
- **容器路徑**：`/app/public/student_data.json`
- **Docker Volume 掛載**：`./public:/app/public`

### 檔案確認
```bash
# 主機上檢查
ls -lh public/student_data.json
# 輸出：-rw-r--r-- 1 ctctim14 users 35K Sep 28 17:34 public/student_data.json

# 容器內檢查
sudo docker exec flb-calendar-nas ls -lh /app/public/student_data.json
# 輸出：-rw-r--r--    1 1026     users      34.8K Sep 28 09:34 student_data.json
```

## ✅ 解決方案

### 方案：修改檔案權限為 666

```bash
chmod 666 public/student_data.json
```

**為什麼選擇 666？**
- `6` (所有者): 讀寫權限
- `6` (群組): 讀寫權限
- `6` (其他): 讀寫權限

這樣容器內的 nextjs 用戶（UID 1001）就可以寫入檔案了。

### 不選擇軟連結的原因

之前考慮的軟連結方案（連接 `/volume1/web/flb-calendar/public/student_data.json` 和 Docker 路徑）**不適用**，因為：
1. 系統已經通過 Docker Volume 正確掛載
2. 真正的問題是權限，不是路徑
3. `/volume1/web/flb-calendar/` 是 Nginx 的舊路徑，與當前問題無關

## 📝 技術細節

### Docker Volume 掛載機制
```yaml
volumes:
  - ./public:/app/public  # 主機的 ./public 掛載到容器的 /app/public
```

### 檔案權限對應
```
主機 UID 1026 (ctctim14) → 容器內顯示為 UID 1026
容器 UID 1001 (nextjs)   → 需要寫入權限
```

### 權限模式說明
- `644`（原始）：所有者可讀寫，其他人只讀 ❌
- `666`（修復後）：所有人可讀寫 ✅
- `777`：所有人可讀寫執行（不建議用於 JSON 檔案）

## 🎯 總結

- **問題**：Docker 容器內的 nextjs 用戶無法寫入 student_data.json
- **原因**：檔案權限為 644，只有所有者可寫入
- **解決**：修改權限為 666，允許所有用戶讀寫
- **驗證**：簽到後重新打開，確認狀態保留
