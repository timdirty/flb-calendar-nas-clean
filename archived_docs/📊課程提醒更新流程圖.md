## 🔍 防重複機制詳解

### ID 生成規則

```javascript
const reminderId = `${type}_${teacherName}_${eventDate}_${eventTime}`;
```

### 範例

```
課程: 2025-10-17 09:30 SPM (講師: 王老師)

生成的提醒 ID:
├─ today_王老師_2025-10-17_09:30        (今日提醒)
├─ tomorrow_王老師_2025-10-17_09:30     (隔日提醒，前一天創建)
└─ before-class_王老師_2025-10-17_09:30 (課前提醒)
```

### 檢查流程

```
每 5 分鐘執行時:
├─ 從 CalDAV 獲取課程
├─ 生成提醒 ID: today_王老師_2025-10-17_09:30
├─ 檢查 existingReminders 中是否已存在此 ID
│
├─ 如存在:
│  └─ console.log('⏭️ 提醒已存在')
│  └─ 跳過，不創建
│
└─ 如不存在:
   └─ 創建新提醒
   └─ push 到 existingReminders
   └─ 儲存到 reminders.json
```

## 🌅 午夜清理的重要性

### 為什麼需要午夜清理？

```
問題：如果不清理會怎樣？

範例：
2025-10-17 的課程提醒
├─ 10/16 18:00 創建隔日提醒
├─ 10/17 00:00 創建今日提醒 + 課前提醒
│
如果不清理:
├─ 隔日提醒仍然存在（但已經過期）
├─ 今日提醒被創建（正確）
├─ 課前提醒被創建（正確）
│
結果:
└─ reminders.json 越來越大 ❌
└─ 包含大量過期提醒 ❌
└─ 影響查詢效能 ❌
```

### 午夜清理做什麼？

```
🌅 forceMidnightCleanupAndReload()

1. 清空所有舊提醒
   ├─ reminders: []
   └─ studentReminders: []

2. 重新從 Google Sheets 獲取學生資料
   └─ 確保學生資料是最新的

3. 重新從 CalDAV 創建提醒
   ├─ 只創建今天和明天的課程
   └─ 不會創建過期的課程

4. 重新生成學生提醒
   └─ 基於最新的學生資料和課程

結果:
✅ 系統重新開始，從乾淨狀態
✅ 只保留相關的提醒
✅ 確保資料最新
```
