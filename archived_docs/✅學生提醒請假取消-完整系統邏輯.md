### 2️⃣ 學生提醒生成邏輯

```javascript
reminder-scheduler.js: generateStudentReminders()

步驟 1: 獲取未來課程事件
  └── 從 CalDAV 獲取課程行事曆

步驟 2: 讀取最新學生資料
  └── 從 public/student_data.json 讀取

步驟 3: 生成提醒（雙重防重複檢查）
  └── 對每個課程的每個學生:
      ├── ✅ 檢查 1: 與已存檔的提醒比對
      │   └── 若已存在 → 跳過
      │
      ├── ✅ 檢查 2: 與本次已生成的提醒比對
      │   └── 若已存在 → 跳過
      │
      ├── ✅ 檢查 3: 檢查學生請假狀態
      │   └── 若請假 → 跳過（不生成提醒）
      │
      └── ✅ 若通過所有檢查 → 生成新提醒
          └── status: 'pending'
```

**關鍵程式碼**:
```javascript
// 檢查 1: 已存檔的提醒
const existingReminder = existingStudentReminders.find(r => 
  r.studentName === student.name &&
  r.courseName === event.title &&
  r.courseDate === courseDate
);
if (existingReminder) {
  console.log(`⏭️ 學生提醒已存在（從文件載入）`);
  continue;
}

// 檢查 2: 本次已生成的提醒
const newReminder = newStudentReminders.find(r => 
  r.studentName === student.name &&
  r.courseName === event.title &&
  r.courseDate === courseDate
);
if (newReminder) {
  console.log(`⏭️ 學生提醒已存在（本次已創建）`);
  continue;
}

// 檢查 3: 請假狀態（在生成前檢查）
const attendanceRecord = student.attendance?.find(a => a.date === courseDate);
if (attendanceRecord && (attendanceRecord.present === false || attendanceRecord.present === 'leave')) {
  console.log(`❌ 學生 ${student.name} 在 ${courseDate} 請假，跳過生成提醒`);
  continue;
}
```

### 3️⃣ 發送前二次驗證機制 ⭐ **新增**

```javascript
reminder-scheduler.js: processStudentReminders()

步驟 1: 獲取待發送的提醒
  └── 篩選 status === 'pending' 的提醒

步驟 2: 🔍 發送前重新驗證（防止資料變動）
  └── 重新讀取最新的 student_data.json
  └── 對每個待發送提醒:
      ├── 查找對應學生
      ├── 檢查該課程日期的請假狀態
      │
      └── 若學生已請假:
          ├── status → 'cancelled'
          ├── cancelReason → '學生請假'
          ├── cancelledAt → 當前時間
          └── 不發送此提醒

步驟 3: 發送通過驗證的提醒
  └── 只發送 validReminders
```

**關鍵程式碼**:
```javascript
// 🔍 發送前重新驗證學生請假狀態
console.log('🔍 發送前重新驗證學生請假狀態...');
const studentDataPath = path.join(__dirname, 'public', 'student_data.json');
const studentData = JSON.parse(fs.readFileSync(studentDataPath, 'utf8'));
const students = studentData.students || [];

const validReminders = [];
const cancelledReminders = [];

for (const reminder of pendingStudentReminders) {
  const student = students.find(s => s.name === reminder.studentName);
  
  if (!student) {
    console.log(`⚠️ 找不到學生資料: ${reminder.studentName}，保留提醒`);
    validReminders.push(reminder);
    continue;
  }

  const courseDate = reminder.courseDate;
  const attendanceRecord = student.attendance?.find(a => a.date === courseDate);

  if (attendanceRecord && (attendanceRecord.present === false || attendanceRecord.present === 'leave')) {
    console.log(`❌ 學生 ${reminder.studentName} 在 ${courseDate} 請假，取消發送提醒`);
    reminder.status = 'cancelled';
    reminder.cancelReason = '學生請假';
    reminder.cancelledAt = new Date().toISOString();
    cancelledReminders.push(reminder);
  } else {
    validReminders.push(reminder);
  }
}

if (cancelledReminders.length > 0) {
  console.log(`🚫 取消 ${cancelledReminders.length} 個提醒（學生請假）`);
  this.saveReminders(remindersData); // 儲存更新的狀態
}

console.log(`✅ 確認可發送 ${validReminders.length} 個學生提醒`);
const results = await this.sendStudentReminders(validReminders);
```

## 🛡️ 雙重防護機制

### 防護 1：生成時檢查
**位置**: `generateStudentReminders()`  
**時機**: 創建提醒時  
**作用**: 若學生已請假，不生成提醒

### 防護 2：發送前驗證 ⭐ **新增**
**位置**: `processStudentReminders()`  
**時機**: 發送提醒前  
**作用**: 若學生在生成後請假，取消發送

**為什麼需要雙重防護？**
- 學生可能在提醒生成後才請假
- student_data.json 每 5 分鐘更新一次
- 提醒可能提前數小時或數天生成
- 發送前需確保資料是最新的
