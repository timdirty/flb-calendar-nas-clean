# 📋 停課/請假/代課 - 處理機制完整說明

## 🎯 核心答案

### ✅ 停課/請假：系統會自動跳過，不發送提醒
### ⚠️ 代課：需要在 CalDAV 修改講師欄位，才會發送給正確的代課講師

---

## 🔍 系統運作機制

### 1️⃣ 關鍵字檢測機制

系統會檢查課程標題是否包含**跳過關鍵字**：

```json
// system-settings.json
{
  "skipKeywords": {
    "enabled": true,
    "keywords": [
      "停課",
      "請假",
      "取消",
      "暫停"
    ]
  }
}
```

**運作邏輯**：
```javascript
// reminder-scheduler.js

// 檢查課程標題
const skipKeywords = ['停課', '請假', '取消', '暫停'];
const hasSkipKeyword = skipKeywords.some(keyword => event.title.includes(keyword));

if (hasSkipKeyword) {
  console.log(`⏭️ 跳過提醒 - 行事曆標題包含跳過關鍵字: ${event.title}`);
  return null; // 不創建提醒
}
```

## 📊 各種情況的處理方式

### 情況 1️⃣：停課

#### ✅ 正確做法：在課程標題加上「停課」

**Synology Calendar 操作**：
```
原標題: SPM 六 0930-1100
修改為: SPM 六 0930-1100 停課

或

原標題: Python 進階班 三 1400-1600
修改為: [停課] Python 進階班 三 1400-1600
```

**系統行為**：
```
08:00 - 系統檢查 CalDAV
        ├─ 發現課程: "SPM 六 0930-1100 停課"
        ├─ 檢測到關鍵字: "停課"
        └─ ⏭️ 跳過創建提醒 ✅

08:05 - 系統檢查 CalDAV
        └─ 同樣跳過 ✅

18:00 - 不會發送隔日提醒 ✅
```

**前端顯示**：
- 提醒管理介面中**不會出現**此課程的提醒
- 講師**不會收到** LINE 通知

---

### 情況 2️⃣：講師請假

#### ✅ 正確做法 A：在課程標題加上「請假」

```
原標題: ESM 一 1530-1700
修改為: ESM 一 1530-1700 請假

或

修改為: [講師請假] ESM 一 1530-1700
```

**系統行為**：
```
系統每 5 分鐘檢查:
├─ 發現關鍵字: "請假"
└─ ⏭️ 跳過創建提醒 ✅

結果:
└─ 講師不會收到提醒 ✅
```

#### ✅ 正確做法 B：直接在 CalDAV 刪除課程

```
Synology Calendar:
└─ 找到該課程
└─ 刪除 🗑️
```

**系統行為**：
```
系統每 5 分鐘檢查:
├─ 從 CalDAV 獲取課程
├─ 找不到該課程
└─ 不創建提醒 ✅

結果:
└─ 講師不會收到提醒 ✅
```

### 情況 3️⃣：學生請假

#### 學生請假的處理方式不同！

**處理流程**：
1. 在 Google Sheets 中標記學生請假
2. 系統每 5 分鐘更新 `student_data.json`
3. 生成學生提醒時檢查請假狀態
4. 發送前再次驗證請假狀態

**詳細機制**：
```
Google Sheets:
├─ 找到學生: 沈嘉桐(桐桐)
├─ 找到日期: 2025-10-18
└─ 標記請假: present = false 或 "leave"

系統行為:
├─ 每 5 分鐘更新 student_data.json
├─ 生成提醒時檢查請假 → 跳過 ✅
│
└─ 發送前二次驗證 → 若請假則取消 ✅
    ├─ status = 'cancelled'
    ├─ cancelReason = '學生請假'
    └─ 不發送提醒
```

**參考文件**：
- `✅學生提醒請假取消-完整系統邏輯.md`

### 情況 4️⃣：代課 ⚠️ 重點！

#### ❌ 錯誤做法：只改標題

```
錯誤示範:
原標題: SPM 六 0930-1100 (講師: 王老師)
修改為: SPM 六 0930-1100 代課 (講師欄位仍是: 王老師)

問題:
├─ "代課" 不在 skipKeywords 清單中
├─ 系統仍會創建提醒
└─ 提醒會發送給原講師（王老師）❌
```

#### ✅ 正確做法：修改講師欄位

**Synology Calendar 操作步驟**：

1. **開啟課程編輯**
   ```
   找到課程 → 點擊編輯
   ```

2. **修改講師欄位**
   ```
   原本: 王老師
   改為: 李老師
   
   (標題可加可不加"代課"字樣)
   標題: SPM 六 0930-1100 代課
   ```

3. **儲存**

**系統行為**：
```
08:00 - 系統檢查 CalDAV
        ├─ 發現課程: "SPM 六 0930-1100 代課"
        ├─ 講師欄位: event.instructor = "李老師"
        ├─ 沒有停課/請假關鍵字
        └─ ✅ 創建提醒（講師: 李老師）

18:00 - 發送隔日提醒
        └─ 📤 發送給李老師 ✅

09:00 - 發送課前提醒
        └─ 📤 發送給李老師 ✅
```

**前端顯示**：
```
提醒管理介面:
├─ 講師: 李老師
├─ 課程: SPM 六 0930-1100 代課
├─ 狀態: 待發送
└─ 會正常發送給李老師 ✅
```

#### ⚠️ 重要提醒

**如果要「代課但不發提醒」**：
```
修改標題為: SPM 六 0930-1100 代課 停課

說明:
├─ 有「停課」關鍵字
└─ 系統會跳過，不發送任何提醒
```

## 🛡️ 已創建提醒的處理

### 問題：如果提醒已經創建，才決定停課怎麼辦？

```
時間線:
10/16 00:00 - 午夜清理，創建 10/17 課程的隔日提醒 ✅
10/16 14:00 - 講師臨時決定停課 ⚠️
10/16 18:00 - 隔日提醒發送時間到了... 會發送嗎？❓
```

#### ⚠️ 當前行為

**會發送！** 因為提醒已經創建了。

#### ✅ 解決方案

**方案 A：手動刪除提醒（立即生效）**
```
1. 前往提醒管理介面
   https://calendar.funlearnbar.synology.me/course-reminder-management.html

2. 找到該提醒

3. 點擊「刪除」按鈕 🗑️

結果: 立即刪除，不會發送 ✅
```

**方案 B：等待午夜清理（次日生效）**
```
1. 在 Synology Calendar 修改課程標題加上「停課」

2. 等待午夜 00:00 清理

3. 系統重新從 CalDAV 獲取課程

4. 發現「停課」關鍵字，不重新創建

結果: 次日開始不會有新提醒 ✅
```

**方案 C：直接刪除 CalDAV 事件（推薦）**
```
1. 在 Synology Calendar 直接刪除課程

2. 手動到提醒管理介面刪除對應提醒

結果: 立即生效，且後續不會重新創建 ✅
```

## 📋 最佳實踐流程

### 停課流程

```
步驟 1: 確認停課決定
  └─ 與學生/家長溝通

步驟 2: 更新 CalDAV
  ├─ 方法 A: 修改標題加上「停課」
  └─ 方法 B: 直接刪除課程（推薦）

步驟 3: 檢查提醒管理介面
  ├─ 若已有提醒 → 手動刪除
  └─ 若無提醒 → 無需操作

步驟 4: 確認
  └─ 系統會在下次檢查（5分鐘內）自動跳過
```

### 代課流程

```
步驟 1: 確認代課講師
  └─ 確認李老師願意代課

步驟 2: 更新 CalDAV ⭐ 重點
  ├─ 開啟課程編輯
  ├─ 修改「講師」欄位: 王老師 → 李老師
  └─ (可選) 修改標題加上「代課」說明

步驟 3: 確認生效
  ├─ 系統下次檢查（5分鐘內）會創建新提醒
  └─ 新提醒的講師是李老師 ✅

步驟 4: 通知
  └─ 李老師會收到提醒
```

### 學生請假流程

```
步驟 1: 確認學生請假
  └─ 家長通知請假

步驟 2: 更新 Google Sheets
  ├─ 找到學生
  ├─ 找到日期
  └─ 標記 present = false 或 "leave"

步驟 3: 系統自動處理
  ├─ 5 分鐘內更新 student_data.json
  ├─ 生成提醒時檢查請假狀態
  └─ 發送前再次驗證

步驟 4: 結果
  ├─ 若已生成提醒 → 發送前取消（status = 'cancelled'）
  └─ 若未生成提醒 → 跳過生成
```

## ⚙️ 系統設定調整

### 新增跳過關鍵字

如果想讓「代課」也自動跳過：

```json
// system-settings.json
{
  "skipKeywords": {
    "enabled": true,
    "keywords": [
      "停課",
      "請假",
      "取消",
      "暫停",
      "代課"  // ⭐ 新增這一行
    ]
  }
}
```

**⚠️ 注意**：這樣做的話，所有標題包含「代課」的課程都不會發送提醒！

**建議**：不要加入「代課」，而是正確修改 CalDAV 的講師欄位。

### 調整檢查間隔

```json
{
  "scheduler": {
    "checkInterval": 5  // 預設 5 分鐘，可改為 1-60 分鐘
  }
}
```

**說明**：
- 越短 = 反應越快，但 API 呼叫越頻繁
- 預設 5 分鐘已經足夠及時

## 🔍 檢查與驗證

### 檢查提醒是否被跳過

**查看後端日誌**：
```bash
tail -f server.log | grep "跳過"
```

**預期輸出**：
```
⏭️ 跳過提醒 - 行事曆標題包含跳過關鍵字: SPM 六 0930-1100 停課
⏭️ 跳過學生提醒 - 行事曆標題包含跳過關鍵字: ESM 一 1530-1700 請假
```

### 檢查提醒的講師

**查看 reminders.json**：
```bash
cat reminders.json | jq '.reminders[] | select(.courseDate == "2025-10-18") | {teacherName, courseName, type}'
```

**預期輸出**：
```json
{
  "teacherName": "李老師",
  "courseName": "SPM 六 0930-1100 代課",
  "type": "tomorrow"
}
```

### 檢查學生請假狀態

**查看 student_data.json**：
```bash
cat public/student_data.json | jq '.students[] | select(.name == "沈嘉桐(桐桐)") | .attendance'
```

**預期輸出**：
```json
[
  {
    "date": "2025-10-18",
    "present": false  // 或 "leave"
  }
]
```
