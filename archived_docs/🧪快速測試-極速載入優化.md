## ⚡ 桌面端測試（預期 < 800ms）

### 1. 基礎測試

1. 開啟 Chrome/Edge（建議使用無痕模式）
2. 按 F12 開啟開發者工具
3. 切換到 Console 標籤
4. 訪問應用網址
5. 觀察 console log

**關鍵指標：**
```
⚡ API請求耗時: [應該 < 300ms]
⚡ 資料處理耗時: [應該 < 200ms]
⚡ 載入事件總耗時: [應該 < 500ms]
🎯 總初始化時間: [應該 < 800ms]
```

**預期改善：**
- 優化前：資源 847ms
- 優化後：資源 300-500ms
- 改善：40-65%

### 3. 講師顏色測試

確認講師顏色正確顯示：

1. 等待頁面完全載入
2. 檢查課程卡片的顏色
3. 觀察 console：
   ```
   🎨 從後端載入失敗，使用隨機顏色    // 先用隨機顏色快速渲染
   ```

- 初始渲染：使用隨機顏色（快速顯示）

## 📱 手機端測試（自動綁定）

### 測試案例 1：正常網路

1. 用手機開啟 LINE LIFF 應用
2. 如果已登入且有綁定記錄，先清除快取
3. 觀察是否自動綁定成功

**預期結果：**
- ✅ 自動識別並綁定講師
- ✅ 顯示「TIM 你好～」（或對應講師名稱）
- ✅ 自動切換到個人行事曆

### 測試案例 2：慢速網路

1. 如果手機支援，開啟「開發者選項」
2. 或使用 Chrome Remote Debugging + Network Throttling
3. 設定為 3G 網路速度
4. 重新載入頁面

**預期結果：**
- ✅ 等待時間增加到 20 秒（不會提早超時）
- ✅ 仍能成功自動綁定
- ✅ 不會顯示「載入資料超時」錯誤

### 測試案例 3：極慢網路

1. 設定為 2G 網路速度（或更慢）
2. 重新載入頁面

**預期行為：**
- 如果超過 20 秒仍未完成：
  ```
  ❌ 載入資料超時，將顯示綁定選單
  ```
- 但如果資料實際上已載入，會智能繼續比對：
  ```
  💡 雖然超時，但資料已載入，繼續比對
  ```

## 🔍 效能比較測試

### 方式一：Chrome DevTools Performance

1. 開啟 DevTools > Performance
2. 點擊 Record（圓形按鈕）
3. 重新載入頁面（Cmd+R / Ctrl+R）
4. 停止錄製
5. 分析各階段耗時

**關鍵指標：**
- DCL (DOMContentLoaded): 應該更早觸發
- Load: 總載入時間應該減少
- JavaScript 執行時間: 應該減少

### 方式二：Lighthouse

1. 開啟 DevTools > Lighthouse
2. 選擇 Performance
3. 點擊 Generate report
4. 比較分數變化

**預期改善：**
- Performance Score: 提升 5-10 分
- First Contentful Paint: 減少 100-300ms
- Time to Interactive: 減少 200-400ms

## ⚠️ 常見問題

### Q1: 載入時間沒有明顯改善？

**可能原因：**
1. 後端快取尚未建立（首次啟動）
2. 網路延遲較高
3. 瀏覽器快取影響測試

**解決方式：**
1. 等待後端快取建立（10-20秒）
2. 使用無痕模式測試
3. 清除瀏覽器快取後重新測試

### Q2: 手機端仍無法自動綁定？

**可能原因：**
1. 網路極度不穩定
2. LIFF SDK 載入失敗
3. 講師資料尚未設定

**檢查步驟：**
1. 確認網路連線正常
2. 查看 console log 的錯誤訊息
3. 確認 teacher_data.json 有該用戶記錄

### Q3: 講師顏色顯示不正確？

**正常現象：**
- 初始渲染使用隨機顏色（快速顯示）
- 1-2秒後自動更新為設定的顏色

**如果始終不正確：**
1. 檢查後端 /api/teachers 是否正常
2. 確認 teacher_data.json 顏色設定
3. 清除快取重新載入
