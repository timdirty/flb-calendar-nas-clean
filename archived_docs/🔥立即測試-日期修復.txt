🔥 日期修復 - 立即測試
============================================

✅ 已修復的問題：
主行事曆生成學習歷程上傳連結時，日期使用 UTC 時區導致日期錯誤

🔧 修復內容：
改為使用本地時區的日期（getFullYear、getMonth、getDate）

🧪 測試步驟：

1. 重新載入主行事曆頁面
   → 按 Ctrl+Shift+R (Windows) 或 Cmd+Shift+R (Mac) 強制刷新
   → 確保載入最新的代碼

2. 打開瀏覽器開發者工具（F12）
   → 切換到 Console 標籤

3. 找到一個已結束的課程
   → 注意看課程卡片上顯示的日期是幾號

4. 點擊「上傳學習歷程」按鈕
   → 在 Console 中查看「🔍 生成學習歷程上傳連結」日誌
   → 檢查以下資訊：
      • startTime: 原始時間字串
      • dateStr: 生成的日期（應該與課程卡片顯示的日期一致）
      • isoDate: ISO 格式的日期（用於比較）

5. 檢查跳轉後的頁面
   → URL 中的 date 參數應該是正確的日期
   → 頁面標題應該顯示正確的日期
   → 應該能看到該日期的已結束課程

🔍 調試重點：

如果日期還是不對，在 Console 中查看：
1. 「🔍 生成學習歷程上傳連結」日誌
   → startDate 顯示的日期是幾號？
   → dateStr 是幾號？
   → 是否與課程卡片顯示的日期一致？

2. 如果 dateStr 正確，但頁面找不到課程，查看：
   → 「📅 日期設定」日誌
   → 「📊 日期範圍篩選結果」日誌
   → 「📊 已結束課程篩選結果」日誌

可能的情況：
A. 課程卡片顯示的是 10月19日，但點擊後 URL 是 10月13日
   → 這表示 startTime 本身就是錯的
   → 需要檢查事件資料從 CalDAV 讀取的時間

B. 課程卡片顯示的是 10月13日，今天是 10月19日
   → 您是在查看舊的課程記錄
   → 這是正常的，系統會帶您到 10月13日的上傳頁面

C. 日期現在正確了
   → 太好了！修復成功 ✅
