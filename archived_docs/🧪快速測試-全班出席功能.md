# 🧪 快速測試 - 全班出席功能

## 🚀 快速開始

### 1️⃣ 部署檔案
```bash

cp public/perfect-calendar-optimized-complete2.html /volume1/web/calendar/

# 或使用快速部署腳本
./強制同步HTML.sh
```

### 2️⃣ 開啟測試頁面
```
https://calendar.funlearnbar.synology.me/perfect-calendar-optimized-complete2.html
```

## ✅ 測試步驟

### 測試一：基本功能測試

1. **打開課程簽到頁面**
   - 長按日曆上的任一課程（1.5秒）
   - 等待簽到模態框彈出

2. **找到「全班出席」按鈕**
   - 位置：在「學生名單」標題的右側
   - 外觀：綠色漸層按鈕，有雙勾圖示

3. **點擊按鈕**
   - 觀察按鈕變為「處理中...」
   - 看到旋轉的載入圖示

4. **確認結果**
   - 等待處理完成（通常 1-2 秒）
   - 看到 Toast 通知顯示處理結果
   - 確認所有學生卡片變為綠色（出席狀態）
   - 檢查底部統計是否更新

### 測試二：部分出席測試

1. **手動標記 1-2 位學生出席**
   - 點擊個別學生的「✅ 出席」按鈕

2. **點擊「全班出席」按鈕**

3. **確認結果**
   - 已出席的學生不會被重複處理
   - Toast 顯示實際標記的學生數量
   - 控制台顯示跳過已出席學生的日誌

### 測試三：課程開始前測試

1. **選擇未來的課程**
   - 找一個開始時間在 10 分鐘以後的課程
   - 打開簽到頁面

2. **點擊「全班出席」按鈕**

3. **確認結果**
   - Toast 顯示「課程尚未開始」或類似訊息
   - 沒有學生被標記為出席

### 測試四：重複點擊測試

1. **快速連續點擊「全班出席」按鈕**
   - 點擊 2-3 次

2. **確認結果**
   - 按鈕在處理期間被禁用
   - 只執行一次全班出席操作

## 🐛 常見問題排查

### 問題 1：按鈕沒有出現
**解決方法**：
- 清除瀏覽器快取（Ctrl+Shift+R 或 Cmd+Shift+R）
- 確認檔案已正確部署到伺服器

### 問題 2：點擊按鈕沒有反應
**解決方法**：
- 檢查控制台是否有 JavaScript 錯誤
- 確認 `markAllPresent()` 函數已正確載入

### 問題 3：部分學生沒有被標記
**解決方法**：
- 檢查控制台日誌，看是否有錯誤訊息
- 確認那些學生的按鈕是否被禁用（課程時間限制）

### 問題 4：處理速度太慢
**原因**：
- 每個學生之間有 100ms 的延遲（避免伺服器過載）
- 這是正常設計
