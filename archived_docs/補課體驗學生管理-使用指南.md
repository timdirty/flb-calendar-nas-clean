## 🚀 使用流程

### 1. 開啟管理後台

訪問：`http://your-server/admin-dashboard.html`

### 2. 進入「補課/體驗學生」頁籤

點擊頂部導航中的「補課/體驗學生」按鈕

### 3. 新增補課學生

**步驟：**

1. 學生類型：選擇「補課學生」
2. 選擇學生：
   - **方式A**：從下拉選單選擇現有學生（推薦）
     - 系統會自動填入課程和原本時段
   - **方式B**：直接輸入學生姓名
3. 填寫補課資訊：
   - 課程名稱：例如 `SPIKE PRO`
   - 補課日期：選擇日期（例如 `2025-10-25`）
   - 上課時段：例如 `一 14:00-16:00`
   - 原本課程時段：自動填入或手動填寫
   - 備註：例如 `因颱風補課`
4. 點擊「新增」按鈕

**範例：**

```
學生類型：補課學生
學生姓名：菲菲
課程名稱：SPIKE PRO
補課日期：2025-10-25
上課時段：一 14:00-16:00
原本時段：日 10:00-12:00
備註：因颱風補課
```

### 4. 新增體驗學生

**步驟：**

1. 學生類型：選擇「體驗學生」
2. 直接輸入學生姓名（通常是新學生）
3. 填寫體驗資訊：
   - 課程名稱：例如 `ESM`
   - 體驗日期：選擇日期
   - 上課時段：例如 `三 15:00-17:00`
   - 備註：例如 `單堂體驗`
4. 點擊「新增」按鈕

**範例：**

```
學生類型：體驗學生
學生姓名：李小華
課程名稱：ESM
體驗日期：2025-10-23
上課時段：三 15:00-17:00
備註：單堂體驗
```

### 5. 查看臨時學生列表

在「臨時學生列表」區域可以看到：

| 類型 | 姓名 | 課程 | 日期 | 時段 | 備註 | 操作 |
|------|------|------|------|------|------|------|
| 補課 | 菲菲 | SPIKE PRO | 2025-10-25 | 一 14:00-16:00 | 因颱風補課 | 🗑️ 刪除 |
| 體驗 | 李小華 | ESM | 2025-10-23 | 三 15:00-17:00 | 單堂體驗 | 🗑️ 刪除 |

### 6. 在簽到頁面使用

1. 前往 `perfect-calendar-optimized-complete2.html`
2. 選擇對應的課程時段（例如：2025-10-25 一 14:00）
3. 補課/體驗學生會自動出現在學生列表中
4. 正常進行簽到操作
5. 簽到記錄會保存到 `temporary_students.json`

### 7. 刪除臨時學生

如果需要手動刪除：

1. 在「臨時學生列表」找到要刪除的學生
2. 點擊「刪除」按鈕
3. 確認刪除

## 🔄 自動清理機制

系統會在**每天凌晨 2:00** 自動執行清理：

```
🕐 [定時任務] 開始清理過期的臨時學生...
🧹 清理過期臨時學生完成：刪除 2 位，剩餘 3 位
```

清理規則：
- 如果 `expiryDate` 已過（當前日期 > 過期日期），則刪除
- 例如：2025-10-25 的補課學生，在 2025-10-26 凌晨 2:00 會被清理

## ⚠️ 注意事項

1. **資料獨立性**：臨時學生資料完全獨立於 `student_data.json`，不會被 Google Sheets 同步覆蓋
2. **簽到記錄**：臨時學生的簽到記錄保存在 `temporary_students.json`，不會影響正常學生
3. **自動過期**：過期日期到達後，臨時學生會在每天凌晨 2:00 自動清理
4. **剩餘堂數**：補課學生顯示 `-1` 堂，體驗學生顯示 `1` 堂
5. **唯一識別**：臨時學生的 `id` 以 `temp_` 開頭，用於區分正常學生

## 🔧 故障排除

### 問題1：臨時學生沒有出現在簽到頁面

**檢查：**
1. 確認日期和時段是否正確
2. 檢查 `periodParsed` 是否正確解析
3. 查看瀏覽器 Console 是否有錯誤

### 問題2：簽到記錄沒有保存

**檢查：**
1. 確認 `temporary_students.json` 檔案權限
2. 查看伺服器 log 是否有錯誤
3. 確認 `/api/update-student-attendance` API 是否正常

### 問題3：臨時學生沒有自動清理

**檢查：**
1. 確認伺服器是否持續運行
2. 查看 log 確認排程是否啟動
3. 手動執行清理函數測試
