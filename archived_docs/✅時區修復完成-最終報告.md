## 一、問題根源

### 1.1 主要問題
**`synology-calendar-client.js` Line 194**
```javascript
❌ start: startDate.toISOString()  // 返回 UTC 時間 "2025-10-11T08:10:00.000Z"
```

**影響**：
- Synology API 返回的 `dtstart` 是 UTC timestamp
- `toISOString()` 返回 UTC 時間字串
- `reminder-scheduler.js` 誤以為是台灣時間
- 導致所有提醒時間計算錯誤 8 小時

### 1.2 次要問題
**多處使用錯誤的時區轉換**
```javascript
❌ Date.UTC(year, month-1, day, hour-8, minute)
```

**問題**：
1. 當 `hour - 8 < 0` 時會跨日錯誤
2. 凌晨課程（00:00-07:59）會計算到前一天
3. 提醒時間不準確

## 二、修復內容

### 2.1 synology-calendar-client.js ✅
**Line 185-219**: 修改事件時間格式化

**修復前**：
```javascript
start: startDate.toISOString()  // "2025-10-11T08:10:00.000Z" (UTC)
```

**修復後**：
```javascript
const startTaiwanStr = startDate.toLocaleString('sv-SE', { 
    timeZone: 'Asia/Taipei',
    year: 'numeric',
    month: '2-digit',
    day: '2-digit',
    hour: '2-digit',
    minute: '2-digit',
    second: '2-digit',
    hour12: false
}).replace(' ', 'T');

start: startTaiwanStr  // "2025-10-11T16:10:00" (台灣時間)
```

**效果**：所有 `event.start` 和 `event.end` 現在都是台灣時間格式

## 三、修復方法總結

### 核心原則
使用**明確的時區字串 `+08:00`** 來創建 Date 物件

### 統一模式
```javascript
// ✅ 正確方法
const taiwanTimeStr = `${year}-${month}-${day}T${hour}:${minute}:00+08:00`;
const dateObj = new Date(taiwanTimeStr);

// ❌ 錯誤方法
const dateObj = new Date(Date.UTC(year, month-1, day, hour-8, minute));
```

## 九、技術總結

### 時區處理的正確方式

1. **API 層**：返回明確的時區時間字串
2. **業務層**：使用 `+08:00` 明確指定時區
3. **顯示層**：使用台灣時區工具函數統一處理
4. **避免**：手動計算時區偏移（`hour - 8`）

### ECMAScript Date 物件規範

```javascript
// 帶時區的 ISO 字串
new Date("2025-10-11T16:10:00+08:00")  // 明確指定台灣時間

// 不帶時區的 ISO 字串
new Date("2025-10-11T16:10:00")        // 視為本地時間（有歧義）

// UTC 時區的 ISO 字串
new Date("2025-10-11T16:10:00Z")       // 明確指定 UTC 時間
```
