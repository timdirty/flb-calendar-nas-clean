# ✅ 共用學生篩選邏輯重構

## 📅 更新日期
2025-10-19

## 🎯 問題描述
`learning-record-upload.html` 頁面顯示 0 位學生，且沒有正確篩選講師。

## 🔧 解決方案
將學生篩選邏輯從後端移到前端，並創建共用函數供所有頁面使用。

## 📝 修改內容

### 1. 創建共用學生篩選模組
**檔案：** `public/js/student-filter.js`

- 創建 `filterStudentsByCourseAndTime(students, course, time)` 函數
- 從 `perfect-calendar-optimized-complete2.html` 複製完整的學生篩選邏輯
- 支援多種時間格式匹配
- 支援課程名稱精準比對（忽略空白）
- 支援時間段基礎匹配（移除週次、代課等後綴）

### 2. 修改後端 API
**檔案：** `server.js`

**修改前：**
```javascript
// 後端在 API 中篩選學生
const students = studentData.students.filter(student => {
    // ... 複雜的篩選邏輯
});
```

**修改後：**
```javascript
// 後端只返回課程元數據，不篩選學生
const coursesWithMetadata = combinedEvents.map(course => {
    return {
        ...course,
        courseName,      // 提取的課程名稱
        coursePeriod,    // 提取的時段資訊
        // 不包含 students 欄位
    };
});
```

### 3. 修改前端頁面
**檔案：** `public/learning-record-upload.html`

**新增：**
```html
<!-- 引入共用學生篩選模組 -->
<script src="/js/student-filter.js"></script>
```

**修改邏輯：**
```javascript
// 1. 從 API 獲取課程資料（不含學生）
const courses = courseData.courses || [];

// 2. 載入學生資料
const studentResponse = await fetch('/student_data.json');
const studentData = await studentResponse.json();

// 3. 使用共用函數篩選學生
allCourses = courses.map(course => {
    const filteredStudents = filterStudentsByCourseAndTime(
        studentData.students,
        course.courseName,
        course.coursePeriod
    );
    
    return {
        ...course,
        students: filteredStudents
    };
});
```

## ✅ 優點

1. **統一邏輯：** 所有頁面使用相同的學生篩選邏輯
2. **易於維護：** 只需修改 `student-filter.js` 即可更新所有頁面
3. **減少後端負擔：** 後端只處理課程資料，不處理學生篩選
4. **前端控制：** 前端可以靈活地調整篩選邏輯
5. **一致性保證：** 確保主日曆和學習歷程上傳頁面的學生列表完全一致
