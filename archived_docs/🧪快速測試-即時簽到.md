# 🧪 快速測試 - 即時簽到更新

## 📋 測試目的
驗證多個手機裝置能即時看到最新的學生簽到狀態（無快取問題）

---

## 🚀 步驟 1：部署更新

### 在 NAS 上執行

```bash
cd /volume1/docker/flb-calendar
./🚀立即部署-即時簽到更新.sh
```

或手動重啟：
```bash
docker-compose restart
```

---

## 📱 步驟 2：準備測試環境

### 需要準備
- ✅ 2 台手機或平板（手機 A 和手機 B）
- ✅ 都能訪問行事曆系統
- ✅ 都已登入 LINE（如果需要）

### 建議組合
- 手機 A：iPhone
- 手機 B：Android
- 或任意兩台不同的裝置

---

## ✅ 步驟 3：執行測試

### 測試案例 1：基本簽到同步

1. **手機 A** - 執行簽到操作：
   ```
   1. 開啟行事曆
   2. 選擇一個課程（例如：SPIKE 六 1600-1800）
   3. 點擊課程進入簽到頁面
   4. 為學生簽到（例如：吳昀衡 → 出席）
   5. 確認簽到成功
   ```

2. **手機 B** - 驗證即時更新：
   ```
   1. 開啟行事曆（或重新整理頁面）
   2. 選擇相同課程（SPIKE 六 1600-1800）
   3. 查看學生名單
   ```

3. **預期結果**：
   - ✅ 手機 B 能看到「吳昀衡」已經簽到（出席）
   - ✅ 剩餘堂數已減少
   - ✅ 不會看到舊的未簽到狀態

---

### 測試案例 2：修改簽到狀態

1. **手機 A**：
   ```
   將「吳昀衡」從「出席」改為「請假」
   ```

2. **手機 B**：
   ```
   重新載入課程學生名單
   ```

3. **預期結果**：
   - ✅ 手機 B 立即看到「請假」狀態
   - ✅ 剩餘堂數恢復

---

### 測試案例 3：瀏覽器快取檢查

**使用瀏覽器開發者工具**：

1. 在手機 B 上開啟瀏覽器
2. 如果是電腦瀏覽器，按 `F12` 開啟開發者工具
3. 切換到 **Network** (網路) 標籤
4. 重新載入頁面
5. 找到 `student_data.json` 請求
6. 查看 **Response Headers**

**預期結果**：
```http
Cache-Control: no-store, no-cache, must-revalidate, private
Pragma: no-cache
Expires: 0
```

**Size 欄位**：
- ✅ 顯示實際大小（例如：52.3 KB）
- ❌ 不應該顯示 "from cache" 或 "from disk cache"

## ❌ 如果測試失敗

### 問題 1：手機 B 看到舊資料

**可能原因**：
1. 瀏覽器強快取
2. 網路代理快取
3. 服務未正確重啟

**解決方法**：
```bash
# 1. 完全清除瀏覽器快取
在瀏覽器設定中清除所有快取

# 2. 強制重新整理
按 Ctrl+Shift+R (或 Cmd+Shift+R)

# 3. 檢查服務狀態
docker-compose ps
docker-compose restart

# 4. 檢查後端程式碼
確認 server.js 中有新增的路由
```

---

### 問題 2：Network 顯示 "from cache"

**可能原因**：
1. 後端路由未生效
2. 前端未加上 no-cache

**檢查方法**：
```bash
# 查看 server.js 是否有修改
grep -A 5 "特別處理 student_data.json" server.js

# 查看前端是否有修改
grep -B 2 -A 5 "cache: 'no-cache'" public/perfect-calendar-optimized-complete2.html
```

---

### 問題 3：簽到後資料未更新

**可能原因**：
1. 後端 API 寫入失敗
2. 檔案權限問題

**檢查方法**：
```bash
# 查看完整日誌
docker-compose logs --tail=100

# 檢查檔案權限
ls -la public/student_data.json

# 查看最近修改時間
stat public/student_data.json
```
