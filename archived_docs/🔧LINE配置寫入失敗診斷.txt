問題分析
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

server.js Line 4820-4891 的 POST /api/line-config 邏輯：
✅ 程式碼正確，會寫入 .env.nas
✅ 有正確的檔案路徑：path.join(__dirname, '.env.nas')
✅ 有 fs.writeFileSync(envPath, envContent)

可能原因：
1. Docker 容器內的 /app/.env.nas 沒有對應到主機的 .env.nas
2. 容器內的檔案權限不允許寫入
3. 只更新了 process.env，但沒有寫入檔案

解決方案 1: 檢查 Volume 掛載
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

檢查 docker-compose.yml 是否有掛載 .env.nas：

volumes:
  - ./.env.nas:/app/.env.nas  ← 需要這一行！

如果沒有，需要添加並重啟：

1. 編輯 docker-compose.yml
2. 在 volumes 區段添加：- ./.env.nas:/app/.env.nas
3. 重啟：sudo docker-compose down && sudo docker-compose up -d

如果容器內沒有寫入權限，修改 server.js 的寫入邏輯：

// 在 POST /api/line-config 中添加錯誤處理
try {
  fs.writeFileSync(envPath, envContent);
  console.log('✅ 寫入成功:', envPath);
} catch (writeError) {
  console.error('❌ 寫入失敗:', writeError.message);
  
  // 嘗試寫入到容器可寫的位置
  const altPath = '/tmp/.env.nas';
  fs.writeFileSync(altPath, envContent);
  console.log('✅ 已寫入到備用位置:', altPath);
}
