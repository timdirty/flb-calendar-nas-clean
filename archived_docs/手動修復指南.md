## ✅ 解決方案

### 方案 1: 設定 LINE Channel Access Token（最重要！）

#### 為什麼失敗？
`.env.nas` 文件缺少 `LINE_CHANNEL_ACCESS_TOKEN`，導致所有 LINE 通知都返回 500 錯誤。

#### 如何修復？

**步驟 1: 取得 LINE Token**
1. 訪問 [LINE Developers Console](https://developers.line.biz/console/)
2. 登入您的帳號
3. 選擇您的 Messaging API Channel
4. 點擊 "Messaging API" 分頁
5. 找到 "Channel access token (long-lived)"
6. 點擊 "Issue" 或複製現有的 Token

**步驟 2: SSH 到 NAS 並設定**

```bash
# 連接到 NAS
ssh -p 1022 ctctim14@funlearnbar.synology.me

# 進入專案目錄
cd /volume1/homes/ctctim14/樂程坊計畫/課程資料/Cursor/講師行事曆檢視/flb-calendar-nas

# 編輯 .env.nas
vi .env.nas
```

**步驟 3: 添加以下行**

按 `i` 進入編輯模式，在文件末尾添加：

```env
# LINE Messaging API
LINE_CHANNEL_ACCESS_TOKEN=您的_Channel_Access_Token_這裡
ADMIN_USER_ID=U0291ce9023f7911a99cf79a54be90de8
```

按 `Esc`，輸入 `:wq` 保存並退出。

**步驟 4: 重啟服務**

```bash
sudo docker-compose down
sudo docker-compose up -d
```

**步驟 5: 驗證**

```bash
# 查看日誌
sudo docker-compose logs --tail=30

# 測試 LINE 通知（替換成您的 User ID）
curl -X POST http://localhost:3001/api/test-line-notification \
  -H "Content-Type: application/json" \
  -d '{"message": "測試訊息", "userId": "U0291ce9023f7911a99cf79a54be90de8"}'
```

## 🚨 常見問題

### Q1: LINE 通知還是失敗？

**檢查**:
```bash
# 查看環境變數
grep LINE_CHANNEL_ACCESS_TOKEN .env.nas

# 檢查日誌
sudo docker-compose logs | grep -i "line"

# 測試 API
curl -X POST http://localhost:3001/api/line-config-status
```

**可能原因**:
1. Token 格式錯誤（有空格或換行）
2. Token 已過期
3. Docker 沒有重啟載入新的環境變數

### Q2: 講師列表還是顯示 [object Object]？

**檢查**:
```javascript
// 在瀏覽器控制台
fetch('/api/teachers')
  .then(r => r.json())
  .then(d => {
    console.log('完整回應:', d);
    console.log('teachers 類型:', typeof d.data.teachers);
    console.log('teachers 內容:', d.data.teachers);
  });
```

**可能原因**:
1. API 返回格式不對
2. 前端 JavaScript 錯誤
3. 緩存問題（Ctrl+F5 強制刷新）

### Q3: 模板保存後沒有生效？

**檢查**:
```bash
# 查看模板文件
cat data/templates.json

# 確認權限
ls -la data/templates.json
```
