### 用戶反饋

用戶發現：沈嘉桐(桐桐) 的學生提醒顯示「待發送」，但該學生明天（2025-10-18）應該是請假狀態。


## 🔍 根本原因分析

### 時間線還原

```
2025-10-16 16:02 📝 系統生成學生提醒
                 ↓
              檢查 student_data.json
                 ↓
              當時沒有 10/18 的請假記錄
                 ↓
              ✅ 判斷為正常上課
                 ↓
              創建提醒並保存到 reminders.json
                 ↓
                 
2025-10-17 某時 📅 Google Sheets 標記請假
                 ↓
              student_data.json 同步更新
              （或還沒更新）
                 ↓
              ❌ 問題：已創建的提醒不會被刪除
                 ↓
              ❌ 19:30 仍然會發送提醒給家長！
```

### 系統缺陷

#### 缺陷 1：提醒創建後不會重新驗證

**原始邏輯**：
```javascript
// processStudentReminders()
const pendingReminders = studentReminders.filter(r => 
  r.status === 'pending' && 
  new Date(r.scheduledTime) <= now
);

// ❌ 直接發送，沒有重新檢查請假狀態
await sendStudentReminders(pendingReminders);
```

**問題**：
- 提醒創建時是正常狀態
- 後續學生請假，提醒狀態不會更新
- 發送時沒有再次驗證，導致錯誤發送

#### 缺陷 2：只在創建時檢查一次

```javascript
// generateStudentReminders() - 只在創建時檢查
if (student.attendance[courseDate] === 'leave') {
  continue; // 跳過
}

// 創建提醒後，就固定保存了
reminder.status = 'pending';
```

**問題**：
- 檢查只發生在**創建時**
- 創建後到發送前（可能相隔數小時或數天）
- 學生狀態變化不會影響已創建的提醒

## 🔧 修復方案

### 新增：發送前二次驗證機制

**位置**：`reminder-scheduler.js` → `processStudentReminders()` (第 1600 行)

**修復邏輯**：
```javascript
// ⭐ 新增：發送前重新驗證學生請假狀態
console.log('🔍 發送前重新驗證學生請假狀態...');
const studentDataPath = path.join(__dirname, 'public', 'student_data.json');
const studentData = JSON.parse(fs.readFileSync(studentDataPath, 'utf8'));
const students = studentData.students || [];

// 過濾出確認可以發送的提醒（重新檢查請假狀態）
const validReminders = [];
const cancelledReminders = [];

for (const reminder of pendingStudentReminders) {
  // 1. 找到對應的學生
  const student = students.find(s => s.name === reminder.studentName);
  
  if (!student) {
    console.log(`⚠️ 找不到學生資料: ${reminder.studentName}，保留提醒`);
    validReminders.push(reminder);
    continue;
  }
  
  // 2. 檢查該日期是否請假
  const courseDate = reminder.courseDate;
  const attendanceRecord = student.attendance?.find(a => a.date === courseDate);
  
  // 3. 如果請假，標記為取消
  if (attendanceRecord && 
      (attendanceRecord.present === false || 
       attendanceRecord.present === 'leave')) {
    console.log(`❌ 學生 ${reminder.studentName} 在 ${courseDate} 請假，取消發送提醒`);
    reminder.status = 'cancelled';
    reminder.cancelReason = '學生請假';
    reminder.cancelledAt = new Date().toISOString();
    cancelledReminders.push(reminder);
  } else {
    // 4. 正常狀態，加入發送列表
    validReminders.push(reminder);
  }
}

// 5. 保存取消的提醒狀態
if (cancelledReminders.length > 0) {
  console.log(`🚫 取消 ${cancelledReminders.length} 個提醒（學生請假）`);
  this.saveReminders(remindersData);
}

// 6. 只發送有效的提醒
console.log(`✅ 確認可發送 ${validReminders.length} 個學生提醒`);
await this.sendStudentReminders(validReminders);
```

## 🎯 修復效果

### 1️⃣ 雙重驗證機制

| 檢查點 | 時機 | 目的 |
|--------|------|------|
| **第一次檢查** | 生成提醒時 | 避免為請假學生創建提醒 |
| **第二次檢查** ⭐ | 發送提醒前 | 確保發送時學生狀態仍然正常 |

### 2️⃣ 自動取消機制

**新增狀態**：`cancelled`

```json
{
  "studentName": "沈嘉桐(桐桐)",
  "status": "cancelled",  // ⭐ 新增狀態
  "cancelReason": "學生請假",
  "cancelledAt": "2025-10-17T11:30:00.000Z"
}
```

**好處**：
- ✅ 提醒不會被刪除（保留記錄）
- ✅ 明確標記取消原因
- ✅ 可追蹤取消時間
- ✅ 管理介面可顯示取消狀態

### 3️⃣ 即時性保證

**時序優勢**：
```
00:00-19:25  每 5 分鐘更新 student_data.json
     ↓
19:30        發送學生提醒時刻
     ↓
   ✅ 讀取最新的 student_data.json
     ↓
   ✅ 使用最新的請假狀態
     ↓
   ✅ 準確判斷是否發送
```

**保證**：
- 發送前**最多 5 分鐘內**的資料
- 如果在 19:25-19:30 之間標記請假
- 系統會在 19:30 發送時檢測到並取消

## 🎯 回答用戶問題

### Q1: 為什麼獲取最新 student_data.json 還會生成提醒？

**A**：因為提醒是**提前生成**的（課程前一天），生成時學生狀態正常。後續標記請假時，**已生成的提醒不會自動更新**。

**現已修復**：發送前會**重新檢查**，確保不會發送給請假學生。

### Q2: 是因為系統一開始先用本地端的檔案嗎？

**A**：不是。系統每 5 分鐘都會從 Google Sheets 更新 student_data.json。

**真正原因**：
1. 提醒在 10/16 生成（當時學生正常）
2. 後來在 10/17 標記請假
3. 修復前：已生成的提醒不會被取消
4. 修復後：發送前會重新驗證並取消

### Q3: 五分鐘後才會更新提醒嗎？

**A**：提醒的**生成**每 5 分鐘檢查一次，但**已生成的提醒**之前不會更新。

**修復後**：
- 提醒狀態會在**發送前（19:30）** 重新驗證
- 無論提醒何時生成，發送時都會檢查最新狀態
- 確保準確性
