# ✅ 時區問題修復 - 學生匹配 (2025-10-19)

## 🐛 問題描述

在學習歷程上傳頁面 (`learning-record-upload.html`)，點擊從日曆跳轉的 SPIKE PRO 課程時，**無法正確匹配到學生**，導致課程學生列表為空。

**URL 範例：**
```
https://calendar.funlearnbar.synology.me/learning-record-upload.html?eventId=20251018T043723-ouqqshoc@cal.synology.com&date=2025-10-19&time=10:00&instructor=TIM
```

**預期結果：**
- SPIKE PRO 日 10:00-12:00 課程應該匹配到 2 位學生：陳杰睿、顏世餘

**實際結果：**
- 學生數：0（沒有匹配到任何學生）

---

## 🔍 問題根因

### 1. 時區解析問題

**CalDAV API 返回的時間格式：**
```javascript
{
  start: "2025-10-19T10:00:00",  // ⚠️ 沒有時區資訊
  end: "2025-10-19T12:00:00"     // ⚠️ 沒有時區資訊
}
```

**JavaScript 的解析行為：**
- 當時間字串**沒有時區資訊**時（如 `"2025-10-19T10:00:00"`），`new Date()` 的行為取決於運行環境
- 在不同環境下可能被解析為：
  - 本地時間（Local Time）
  - UTC 時間（若在 UTC 環境）
  
**導致的錯誤：**
```javascript
// 錯誤的時段提取邏輯
const startDate = new Date("2025-10-19T10:00:00");
// 在 UTC 環境下 → 解析為 UTC 時間
// startDate.getDay() = 0 (正確：星期日)
// startDate.toTimeString() = "10:00:00 GMT+0000" (錯誤！應該是 "18:00:00" 台灣時間)

// 提取的時段：日 1000-1200 (錯誤！應該是 日 1800-2000)
// 學生的時段：日 1000-1200
// 匹配結果：❌ 不匹配
```

### 2. 時段匹配失敗

因為提取的課程時段錯誤，導致：
- **課程時段**：`日 1800-2000`（錯誤的時段）
- **學生時段**：`日 1000-1200`（正確的時段）
- **匹配結果**：❌ 不匹配

---

## ✅ 解決方案

### 修復：在 `server.js` 的 `extractPeriodFromTitle` 函數中

**修復前：**
```javascript
const extractPeriodFromTitle = (title, start, end) => {
  const startDate = new Date(start);  // ⚠️ 時區解析不一致
  const endDate = new Date(end);
  
  const weekdays = ['日', '一', '二', '三', '四', '五', '六'];
  const weekday = weekdays[startDate.getDay()];
  
  const startTime = startDate.toTimeString().slice(0, 5).replace(':', '');
  const endTime = endDate.toTimeString().slice(0, 5).replace(':', '');
  
  return `${weekday} ${startTime}-${endTime}`;
};
```

**修復後：**
```javascript
const extractPeriodFromTitle = (title, start, end) => {
  // ⚠️ 注意：CalDAV 返回的時間字串沒有時區資訊
  // 我們需要將其解析為台灣時間（UTC+8）
  
  let startDate, endDate;
  
  // 檢查時間字串是否包含時區資訊
  if (typeof start === 'string' && !start.includes('Z') && !start.includes('+') && !start.includes('-', 10)) {
    // 沒有時區資訊，手動加上 +08:00 (台灣時區)
    startDate = new Date(start + '+08:00');
    endDate = new Date(end + '+08:00');
  } else {
    // 已經包含時區資訊，直接解析
    startDate = new Date(start);
    endDate = new Date(end);
  }
  
  // 星期對應（使用本地時間方法）
  const weekdays = ['日', '一', '二', '三', '四', '五', '六'];
  const weekday = weekdays[startDate.getDay()];
  
  // 時間格式化（HHMM）- 使用本地時間方法
  const pad = (num) => String(num).padStart(2, '0');
  const startTime = `${pad(startDate.getHours())}${pad(startDate.getMinutes())}`;
  const endTime = `${pad(endDate.getHours())}${pad(endDate.getMinutes())}`;
  
  return `${weekday} ${startTime}-${endTime}`;
};
```

## 💡 經驗總結

### 問題核心
JavaScript 的 `new Date()` 對於**沒有時區資訊的時間字串**的解析行為不一致，會受到運行環境影響。

### 最佳實踐
1. **API 返回時間時務必包含時區資訊**（如 `+08:00` 或 `Z`）
2. **接收時間字串時檢查是否包含時區**，若無則手動補上
3. **使用 `getHours()` 而非 `toTimeString()`**，避免時區轉換問題
4. **測試時考慮不同時區環境**，確保邏輯在所有環境下正確
