# 🚀 快速參考 - 學生資料更新時機

## 📊 更新頻率總覽

| 更新方式 | 頻率 | 觸發時間 | 說明 |
|---------|------|---------|------|
| **自動更新** | 每 5 分鐘 | 24/7 全天候 | 從 Google Sheets 同步最新資料 |
| **Midnight Cleanup** | 每天一次 | 00:00-00:10 | 清理 + 重新整理所有資料 |
| **手動觸發** | 按需 | 隨時 | 透過 API 或管理介面 |

---

## ⏰ 每 5 分鐘執行的流程

```
00:00 → 00:05 → 00:10 → 00:15 → ... → 23:55 (每 5 分鐘)
   ↓       ↓       ↓       ↓              ↓
   
1️⃣ 更新學生資料 (student_data.json)
   ↓
2️⃣ 生成學生提醒（針對明天的課程）
   ├─ 檢查行事曆標題是否有「停課」「請假」
   └─ 檢查每個學生的請假狀態
   ↓
3️⃣ 創建符合條件的提醒
   ↓
4️⃣ 發送該時段的提醒（如果時間到了）
```

---

## 🌅 Midnight Cleanup (00:00-00:10)

```
每天午夜 00:00
   ↓
1️⃣ 清空所有提醒（重新開始）
   ↓
2️⃣ 更新學生資料（從 Google Sheets）
   ↓
3️⃣ 重新生成所有提醒
   ├─ 講師提醒（今日、隔日、課前）
   └─ 學生提醒（明天的課程）
   ↓
4️⃣ 應用最新的請假狀態
   └─ 跳過包含「停課」「請假」的課程
   └─ 跳過個別請假的學生
```

## ⏭️ 請假跳過機制

### 檢查點 1: 行事曆標題

```
課程標題包含跳過關鍵字？
├─ 「停課」 → ❌ 跳過整個課程
├─ 「請假」 → ❌ 跳過整個課程
├─ 「改時間」→ ❌ 跳過整個課程
└─ 都沒有   → ✅ 繼續檢查學生
```

### 檢查點 2: 學生個別狀態

```
遍歷每個匹配的學生
   ↓
檢查 attendance[courseDate]
├─ false   → ❌ 跳過該學生
├─ "leave" → ❌ 跳過該學生
└─ 無記錄   → ✅ 創建提醒
```

## 🎯 關鍵問答

### Q: 學生資料多久更新一次？
**A: 每 5 分鐘更新一次**，從 Google Sheets 同步最新資料。

### Q: 請假狀態何時會生效？
**A: 即時生效**。下一次排程執行（最多 5 分鐘內）就會跳過請假的學生。

### Q: Midnight Cleanup 會做什麼？
**A: 清空所有提醒 → 更新學生資料 → 重新生成所有提醒**。確保新的一天開始時資料完全乾淨。

### Q: 如果在行事曆加上「請假」，提醒會消失嗎？
**A: 會的**。下次排程執行時（最多 5 分鐘內）會檢測到並跳過該課程的所有學生提醒。

### Q: 已經發送的提醒會被撤回嗎？
**A: 不會**。已發送的 LINE 訊息無法撤回，但**未發送的提醒**會被跳過。

## 💡 最佳實踐

### 請假處理流程

**方法 1：在行事曆標題加上「請假」**
```
原標題: "ESM 六 9:30-10:30 到府 第4週"
改為:   "ESM 六 9:30-10:30 到府 第4週請假"

結果: ✅ 所有該課程的學生都不會收到提醒
```

**方法 2：在 Google Sheets 標記學生請假**
```
更新 Google Sheets 中的學生請假狀態
↓
等待最多 5 分鐘（自動同步）
↓
該學生不會收到提醒（其他學生正常）

結果: ✅ 只有請假的學生不會收到提醒
```

### 建議時機

| 情況 | 建議方法 | 原因 |
|------|---------|------|
| 整堂課停課 | 行事曆標題加「停課」 | 一次處理所有學生 |
| 個別學生請假 | Google Sheets 標記 | 只影響該學生 |
| 臨時改時間 | 行事曆標題加「改時間」 | 避免混淆 |
