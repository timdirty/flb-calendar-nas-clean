# 🚨 緊急修復 500 錯誤

## 問題現況

- ❌ 服務顯示 "not running" - 容器已崩潰
- ❌ HTTP 500 錯誤 - 伺服器內部錯誤
- ⚠️ 從日誌看到權限問題：`EACCES: permission denied, open '/app/public/student_data.json'`

## 🎯 根本原因

**權限問題導致服務崩潰！**

容器嘗試讀取 `/app/public/student_data.json` 但沒有權限，導致服務啟動失敗。

---

## 🚀 立即修復（在 SSH 執行）

### 步驟 1: 檢查容器狀態
```bash
cd /volume1/homes/ctctim14/樂程坊計畫/課程資料/Cursor/講師行事曆檢視/flb-calendar-nas
sudo docker-compose ps
```

### 步驟 2: 查看完整錯誤日誌
```bash
sudo docker-compose logs --tail=100
```

### 步驟 3: 修復權限（在 NAS 上，不是在容器內）
```bash
# 修復 public 目錄的所有權限
sudo chmod -R 755 /volume1/homes/ctctim14/樂程坊計畫/課程資料/Cursor/講師行事曆檢視/flb-calendar-nas/public/
sudo chmod 644 /volume1/homes/ctctim14/樂程坊計畫/課程資料/Cursor/講師行事曆檢視/flb-calendar-nas/public/*.json
sudo chmod 644 /volume1/homes/ctctim14/樂程坊計畫/課程資料/Cursor/講師行事曆檢視/flb-calendar-nas/public/*.html
```

### 步驟 4: 重啟容器
```bash
sudo docker-compose down
sudo docker-compose up -d
```

### 步驟 5: 等待並檢查
```bash
sleep 10
sudo docker-compose ps
sudo docker-compose logs --tail=30
```

## 🔍 如果還是失敗

### 方案 A: 檢查是否是 server.js 的問題

```bash
# 查看完整錯誤堆疊
sudo docker-compose logs | grep -A 20 "Error"
```

### 方案 B: 臨時移除有問題的程式碼

如果是 `reminder-scheduler.js` 讀取 `student_data.json` 導致崩潰：

```bash
# 備份 server.js
cp server.js server.js.backup

# 臨時禁用排程器（編輯 server.js）
# 找到並註解掉 reminderScheduler.start() 相關代碼
```

### 方案 C: 檢查 Dockerfile 和用戶權限

問題可能是容器內的用戶 `nextjs` 沒有讀取權限：

```bash
# 查看 public 目錄權限
ls -la public/

# 如果權限不對，全部設為可讀
sudo chmod -R a+r public/
```
