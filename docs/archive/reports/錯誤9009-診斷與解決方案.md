## ⚠️ 目前問題：Synology Calendar API 錯誤 9009

### 可能原因分析

#### 1. 🔴 **API 權限問題**（最可能）
- **症狀**: Synology Calendar API 拒絕更新請求
- **原因**: 測試帳號 (`testacount`) 可能沒有修改日曆事件的權限
- **檢查方法**:
  ```bash
  # 在 Synology NAS 上檢查帳號權限
  # 控制台 → 使用者與群組 → testacount → 應用程式權限 → Calendar
  ```

#### 2. 🟡 **事件 ID 或日曆 ID 格式問題**
- **症狀**: API 無法識別提供的 ID
- **事件 ID 格式**: `20251101T121800-yqouovgc@cal.synology.com`
- **日曆 ID 格式**: `/testacount/jzeblk/`
- **問題**: 可能需要特殊轉義或格式轉換

#### 3. 🟡 **API 版本不相容**
- **當前版本**: SYNO.Cal.Event API version 5
- **問題**: 可能需要使用不同的 API 端點或參數

#### 4. 🟢 **CalDAV vs Synology Calendar API**
- **觀察**: 我們使用的是 Synology Calendar Web API (`/webapi/entry.cgi`)
- **可能**: 應該使用 CalDAV 協議而非 Web API 來更新事件

### 方案 B: 使用 CalDAV 協議更新事件

**理論基礎**: CalDAV 是標準的日曆同步協議，可能比專有的 Synology Calendar API 更可靠。

#### 實作步驟

1. **安裝 CalDAV 客戶端庫**
   ```bash
   npm install caldav-client
   # 或
   npm install dav
   ```

2. **修改 `synology-calendar-client.js`**
   - 添加 CalDAV PUT 方法來更新事件
   - 使用 CalDAV URL 格式：
     ```
     https://funlearnbar.synology.me:9102/caldav/{username}/{calendar-id}/{event-uid}.ics
     ```

3. **示例代碼**（概念）:
   ```javascript
   async updateEventViaCalDAV(calendarId, eventId, updates, existingEvent) {
       // 構建 CalDAV URL
       const caldavUrl = `${this.baseUrl}/caldav${calendarId}${eventId}.ics`;
       
       // 構建 iCalendar 格式的事件
       const icalEvent = this.buildICalEvent(existingEvent, updates);
       
       // 使用 PUT 請求更新
       const response = await axios.put(caldavUrl, icalEvent, {
           auth: {
               username: this.username,
               password: this.password
           },
           headers: {
               'Content-Type': 'text/calendar; charset=utf-8'
           }
       });
       
       return response.status === 200 || response.status === 204;
   }
   ```

**優點**:
- 標準協議，相容性好
- 不依賴 Synology 專有 API
- 可能避免權限問題

**缺點**:
- 需要重構代碼
- 需要處理 iCalendar 格式
