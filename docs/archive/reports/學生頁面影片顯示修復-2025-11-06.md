# 學生頁面影片無法顯示問題 - 修復報告

## 📅 修復日期
2025-11-06

## 🐛 問題描述

用戶反映：**學生頁面的影片可以正常上傳到後端，但前端無法抓取並顯示影片檔案**

### 症狀
- ✅ 影片上傳成功
- ✅ 實體檔案存在於伺服器
- ✅ 縮圖檔案也存在
- ❌ 前端學生卡片不顯示已上傳的影片

---

## 🔍 問題診斷過程

### 1. 驗證後端 API

測試 `/api/learning-records/by-course` 端點，發現 API 正確返回 `newMediaVideos` 陣列。

### 2. 檢查資料結構

發現問題的核心：**資料不一致**

```json
// videos-meta.json (過時的資料)
{
  "id": "189601e9-3413-4a2a-af42-7dca15b97c46",
  "thumbnailFilename": null,  // ❌ 問題！
  "transcodedFilename": null, // ❌ 問題！
  "status": "queued"          // ❌ 問題！
}

// media-meta.json (最新的資料)
{
  "id": "189601e9-3413-4a2a-af42-7dca15b97c46",
  "thumbnail": {
    "filename": "test-video-1762213927843-1762213927843.thumb.jpg" // ✅ 正確！
  },
  "transcoded": {
    "filename": "test-video-1762213927843-1762213927843.webm" // ✅ 正確！
  },
  "status": "ready"  // ✅ 正確！
}
```

### 3. 問題根源

**資料同步問題**：
1. 影片上傳時，`videos-meta.json` 被創建，狀態為 `"queued"`
2. 影片轉碼完成後，`media-meta.json` 被更新，狀態變為 `"ready"`
3. **但是 `videos-meta.json` 沒有同步更新**
4. 後端原本只讀取 `videos-meta.json`，導致返回過時的資料
5. 前端過濾邏輯會跳過 `thumbnailFilename` 為 `null` 的影片

---

## ✅ 解決方案

### 修復 1：後端優先使用 `media-meta.json`

**檔案**：`server.js`  
**位置**：`/api/learning-records/by-course` 端點（兩處）

**修改內容**：
1. 優先讀取 `media-meta.json`（資料更完整且即時更新）
2. 從 `media-meta.json` 中提取影片類型的檔案
3. 將 `media-meta.json` 的結構轉換為 `newMediaVideos` 格式
4. 如果 `media-meta.json` 不存在或沒有影片，回退到 `videos-meta.json`（向下兼容）

**程式碼**：
```javascript
// 優先使用 media-meta.json（資料更完整且即時更新）
if (fs.existsSync(mediaMetaPath)) {
  const content = fs.readFileSync(mediaMetaPath, 'utf8');
  const mediaMeta = JSON.parse(content);
  if (mediaMeta.files && Array.isArray(mediaMeta.files)) {
    // 篩選出影片類型的檔案
    newMediaVideos = mediaMeta.files.filter(f => {
      if (!f || !f.type || !f.type.startsWith('video/')) return false;
      const videoPath = path.join(fullPath, f.filename || '');
      return fs.existsSync(videoPath);
    }).map(f => ({
      id: f.id,
      filename: f.filename,
      originalName: f.filename,
      transcodedFilename: f.transcoded && f.transcoded.filename || null,
      thumbnailFilename: f.thumbnail && f.thumbnail.filename || null,
      uploadedAt: f.uploadedAt,
      fileSize: f.fileSize,
      status: f.status || 'unknown'
    }));
  }
}

// 回退到 videos-meta.json（向下兼容）
if (newMediaVideos.length === 0 && fs.existsSync(videosMetaPath)) {
  // ... 原有的 videos-meta.json 讀取邏輯
}
```

**修改位置**：
- 學生記錄讀取（第 17181-17229 行）
- 課程總覽讀取（第 17091-17139 行）

### 修復 2：前端放寬影片過濾條件

**檔案**：`public/js/pages/learning-record-upload.js`  
**位置**：`applyExistingRecordToCard` 函數（第 6016-6029 行）

**修改內容**：
移除「必須有 `thumbnailFilename` 才顯示」的限制，改為只過濾掉明確失敗的影片。

**原有邏輯**：
```javascript
// ❌ 太嚴格：只保留有縮略圖的
if (!item.thumbnailFilename || item.thumbnailFilename.trim() === '') {
  return false; // 過濾掉
}
```

**修改後**：
```javascript
// ✅ 寬鬆：只過濾掉失敗的
if (item.status === 'failed' || item.status === 'error') {
  return false; // 過濾掉
}
// 即使 thumbnailFilename 為 null，也保留（可能縮圖存在但 meta 未更新）
return true;
```
