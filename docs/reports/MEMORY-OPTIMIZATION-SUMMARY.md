## 🎯 問題描述

### 主要問題
1. **記憶體溢出（OOM）**：一次選擇多個大檔案時，iPhone 瀏覽器崩潰
2. **崩潰後持續失敗**：頁面重載後，即使選擇小檔案也持續崩潰
3. **文字更新阻塞**：上傳媒體時無法同步更新文字欄位

### 根本原因
- 立即為所有檔案創建 Blob URL 和預覽
- Blob URL 洩漏（29 處創建但清理不完整）
- Canvas 與 Video 元素殘留
- 事件監聽器未正確移除

### 階段 2：智能分批上傳系統

**檔案**: `public/js/pages/learning-record-upload.js` (Line 530-737, 10229-10530)

**功能**:
- ✅ 檔案大小分類（極小/小/中/大/超大）
- ✅ 智能排序（優先小檔案、圖片優先於影片）
- ✅ 動態批次創建（根據檔案大小調整批次大小和延遲）
- ✅ 佔位符預覽（先顯示灰色方塊，再逐步替換為實際預覽）
- ✅ 檔案數量與大小驗證（最多 20 個檔案，總大小 < 500MB）

**檔案分類標準**:
| 類別   | 大小範圍    | 批次大小 | 延遲時間 |
|--------|------------|----------|----------|
| 極小   | < 5MB      | 5 個/批  | 100ms    |
| 小     | 5-20MB     | 3 個/批  | 300ms    |
| 中     | 20-50MB    | 2 個/批  | 500ms    |
| 大     | 50-150MB   | 1 個/批  | 1000ms   |
| 超大   | > 150MB    | 1 個/批  | 1500ms   |

**新增函數**:
- `classifyFileBySize(file)` - 檔案大小分類
- `classifyAndSortFiles(files)` - 檔案分類與排序
- `createFileBatches(classifiedFiles)` - 創建批次
- `validateFilesBeforeUpload(files)` - 檔案驗證

**使用者體驗改善**:
1. 選擇檔案後立即顯示佔位符（灰色方塊 + 檔名 + 大小 + 分類標籤）
2. 逐批替換佔位符為實際預覽（小檔案先完成）
3. 每個佔位符顯示處理狀態：
   - ⏳ 等待處理...
   - 🔄 處理中...
   - ✅ （完成後消失）
   - ❌ 處理失敗（錯誤時顯示）

### 階段 3：記憶體壓力監控器（主動防止 OOM）

**檔案**: `public/js/pages/learning-record-upload.js` (Line 328-528)

**功能**:
- ✅ 每 5 秒自動檢測記憶體使用率
- ✅ 根據記憶體壓力自動調整處理策略
- ✅ 四種模式：normal / degraded / warning / critical
- ✅ 自動降級（減少批次大小、跳過縮圖生成）
- ✅ 緊急清理（記憶體 > 95% 時執行）

**記憶體模式**:
| 模式      | 記憶體使用率 | 動作                                  |
|-----------|-------------|---------------------------------------|
| Normal    | < 70%       | 正常處理                              |
| Degraded  | 70-85%      | 減少批次大小為 2、增加延遲為 1000ms   |
| Warning   | 85-95%      | 顯示警告、跳過縮圖生成               |
| Critical  | > 95%       | 執行緊急清理、顯示錯誤提示           |

**新增類別**:
- `MemoryPressureMonitor` - 記憶體壓力監控器（單例模式）

**全域變數**:
- `window.__memoryMode` - 當前記憶體模式
- `window.__memoryRatio` - 當前記憶體使用率

**頁面載入時自動啟動**:
```javascript
// 在 initializePage() 中啟動
memoryMonitor.start();
```

## 📞 問題排查

### 常見問題

**Q1: 頁面載入後仍然崩潰？**
```
A: 
1. 檢查瀏覽器 Console 是否有錯誤
2. 手動執行: window.__emergencyMemoryCleanup()
3. 清除瀏覽器緩存並重新載入
4. 檢查記憶體狀態: window.__checkMemoryPressure()
```

**Q2: 佔位符沒有替換為實際預覽？**
```
A:
1. 檢查 Console 是否有「處理批次 X / Y」日誌
2. 檢查是否有 JavaScript 錯誤
3. 確認檔案格式支援（image/*, video/*）
```

**Q3: 文字無法並行更新？**
```
A:
1. 確認是否有調用 scheduleTextOnlyUpload()
2. 檢查 textUploadTimer 是否正確設置
3. 查看 Console 是否有「[文字上傳]」相關日誌
```

**Q4: 記憶體監控器未啟動？**
```
A:
1. 檢查 memoryMonitor.getStatus()
2. 確認 initializePage() 有被調用
3. 查看 Console 是否有「記憶體壓力監控器已啟動」日誌
```
