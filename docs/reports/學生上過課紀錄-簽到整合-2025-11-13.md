# 學生上過課紀錄 — 簽到整合（2025-11-13）

## 變更摘要
- `/api/attendance/fast` 與 `/api/attendance/queue` 在簽到成功（僅計入 `present`）後，會將學生姓名、課別、課程主題、講師與課程時間寫入 Google Sheet「學生上過的課」。
- 新增 `StudentCourseHistoryLogger` 服務，使用 service account 直寫指定工作表，具備批次排程／去重／自動建表標題列能力。
- 前端 `perfect-calendar-modular.html` 在開啟簽到系統時會附帶 `eventId`、課程類別與推導出的 `courseTopic`，並把資訊傳給後端，避免阻塞 UI。
- 後端若前端未提供主題／課別，會從 `eventsCache` 中比對 `eventId+日期` 自動推導，確保資料完整。
- 2025-11-14：新增 `Record Key` 欄位（隱藏）紀錄 `date|student|course|topic`，並在簽到被改為缺席/請假時立即刪除 Sheet 列與快取 key，同時 `courseName` 改採行事曆標題，避免課別欄位重複。
- 2025-11-14：課別值在寫入 logger 前會自動去除全形空白與尾端的「課 / 課程」後綴，SPIKE 類別統一顯示為 `SPIKE`，避免管理頁重複出現同名課別。
- 2025-11-14：講師簽到畫面會自動解析行事曆描述中的「教案／教學主題」，預填至「課程內容」輸入框並提供提示膠囊與重新套用/清除按鈕，加速講師提交報表。

## 缺席同步刪除
1. `StudentCourseHistoryLogger` 會在 append 時寫入 `Record Key`；若教師改判「缺席/請假」，後端會呼叫 `removeRecord()`：
   - 以 key 尋找 `L` 欄符合的列並刪除。
   - 從 `recentKeys` 快取移除該 key，下次再簽到即允許重新寫入。
2. `/api/attendance/fast` 及 `/api/attendance/queue` 只要 `mark !== 'V'`（缺席或請假）就會觸發上述刪除；Google Sheets 主體仍由原 API 更新缺席標記。
3. 若人工在 Sheet 手動刪除列，仍需重啟後端或手動清空 `recentKeys` 才能立刻重新寫入，屬於刻意的安全防呆。

## 寫入流程
1. 講師在行事曆長按課程開啟簽到視窗 → `window.currentAttendanceData` 儲存 `eventId/courseTopic/courseCategory`。
2. 前端呼叫 `/api/attendance/fast` 或 `/api/attendance/queue` 時加入 `teacher/courseTime/eventId/courseTopic/courseCategory/lessonUrl` 欄位。
3. 後端簽到成功後：
   - 立即更新 `student_data.json`（既有流程）。
   - 透過 `resolveCourseHistoryMeta()` 自動補齊缺值（從 `eventsCache` 解析描述中的 `課程主題`）。
   - 呼叫 `StudentCourseHistoryLogger.enqueueLog()`，以背景佇列 10 筆為單位寫入 Google Sheet；若簽到狀態變為缺席/請假，則改呼叫 `removeRecord()` 刪除對應列。
4. `attendance-queue-manager` 若後台重試成功，同步呼叫 logger，保持兩種簽到路徑資料一致。

## 講師簽到教案預填（2025-11-14）
1. 行事曆事件的描述若包含「課程主題／教學主題／教案／教案名稱」欄位，前後端會同步抽取文字並寫入 `data-event-topic` 與 `courseTopic`；若描述只有 Notion 教案連結，也會取代為教案標題。
2. 打開講師簽到視窗時，系統會顯示「✨ 已自動帶入教案主題」膠囊，僅在輸入框為空時覆寫文字；講師需點「使用預填內容」才視為確認並恢復既有自動提交倒數（若有輸入也會自動視為已確認）。
3. 膠囊仍提供「重新套用教案主題／清除」按鈕：重新套用會重新抓取描述文字並回到「待確認」狀態；清除則把輸入框清空但保留重新套用選項，確保講師能快速在預設與自訂文字間切換。
4. 沒有偵測到教案主題時，膠囊不會出現，流程維持原樣；仍可手動輸入或直接送出報表。

## 環境變數（`.env.nas` / `.env copy.nas`）
```
COURSE_HISTORY_SPREADSHEET_ID=   # 預設沿用既有 Google Sheet ID，可留空
COURSE_HISTORY_SHEET_NAME=學生上過的課
DISABLE_COURSE_HISTORY_LOGGER=false
```
若未指定 `COURSE_HISTORY_SPREADSHEET_ID`，logger 會沿用 `google-sheets-client` 內建的 `SPREADSHEET_ID`。

## 驗證步驟
1. `PORT=3002 DISABLE_AUTO_REMINDERS=true npm run dev > /tmp/npm-dev.log 2>&1 & echo $!`
2. 於 `perfect-calendar-modular.html` 選課並送出簽到（需點擊「出席」）。
3. 觀察後端 log：
   - `✅ Google Sheets 更新成功`（既有）
   - `✅ 已寫入 1 筆學生上過課紀錄`
4. 開啟 Google Sheet → 該工作表應新增列，欄位順序：Timestamp / Date / Course Time / Student Name / Course Category / Course Name / Course Topic / Teacher / Source / Event ID / Lesson URL / Record Key（建議隱藏）。
5. 重新簽到同一學生同一天同課別，應被 recent cache 過濾，不會重複寫入。

## 回滾方式
- 設定 `DISABLE_COURSE_HISTORY_LOGGER=true` 後重啟服務，即可停用背景寫入。
- 移除新增的 env 變數並刪除 `StudentCourseHistoryLogger` 服務檔案即可完全回復本次改動（同時記得還原前端送出的新欄位）。
