## ⚠️ 常见问题

### 问题 1: 上传失败，显示 "error code 119"
**原因**: SID 参数问题  
**解决**: 检查 synology-drive-client.js 的 uploadFile 方法，确保 SID 在 URL 参数中

### 问题 2: 进度条不动
**原因**: XMLHttpRequest 进度事件未触发  
**解决**: 检查是否设置了 xhr.upload.addEventListener('progress', ...)

### 问题 3: 文件上传成功但找不到
**原因**: 路径构建错误  
**解决**: 检查 drive-path-manager.js 的路径构建逻辑

### 问题 4: 预览时显示 404
**原因**: 代理路径错误或 SID 失效  
**解决**: 
1. 检查 buildDirectFileUrl() 函数
2. 确认 /api/drive-media/* 端点正常
3. 检查 Drive 客户端 SID 是否有效

## 4. Pending Upload Persistence 測試（2025-11-13 新增）

> 目的：驗證「學生 ↔ 課程總覽 ↔ 其他頁」切換時，所有尚未同步的縮圖與 Upload Center 任務都能持續存在並快速復原。

### 4.1 同課程內學生 ↔ 課程總覽切換 ⏳
- **步驟**：在學生卡片排隊 2 張照片 + 1 支影片，確認 Upload Center 出現 3 筆任務；切換到「課程總覽」停留數秒後再回到「學生」。
- **預期**：回到學生頁時所有 pending 縮圖仍在原卡片，進度/狀態文字不會重置，Upload Center 無新增副本。

### 4.2 課程清單 ↔ 學生頁切換 ⏳
- **步驟**：開始學生上傳後返回「課程清單」（Router step=`select`），再選同一堂課回到學生頁。
- **預期**：`preserveActiveUploadNodes()` + `reattachAllShadowBuffers()` 保留縮圖位置；`restorePendingUploads()` 僅在缺失節點時重新渲染。

### 4.3 課程總覽 ↔ 其他功能頁面 ⏳
- **步驟**：課程總覽排隊照片/影片後跳轉至 `parent-response-stats.html` 或 `admin-dashboard.html`，再返回切到課程總覽。
- **預期**：`overviewPhotosPreviews` 仍包含 pending 縮圖；若被銷毀，`renderOverviewPendingList()` 會重建（含 remove 按鈕）。Upload Center 任務與本地狀態同步。

### 4.4 頁面重新整理 / App 背景切回 ⏳
- **步驟**：同時讓學生與課程總覽存在 pending 檔案，重新整理頁面或讓 LIFF App 進入背景再回前景。
- **預期**：`sessionStorage` 中的 PendingMediaStore 會在 1 秒內復原所有縮圖；Upload Center 項目保持 `排隊中 / 上傳中` 狀態。

> 完成後請在對應項目加上 ✅，並附上 Console / Screenshot，若失敗請記錄 `PendingMediaStore.listAll()` 與 `uploadShadowHost` 內容以利除錯。

### 4.5 UploadCenter 事件橋接 ⏳
- **步驟**：
  1. 於 DevTools 監聽 `upload-center-update`（`monitorEvents(window, 'upload-center-update')`）。
  2. 觸發學生或課程總覽上傳，觀察 `queued → progress → done/error` 事件是否依序出現，並確認 `detail.task.meta.tempId` 與 `courseKey`。
  3. 切換視圖或重新整理後讓上傳延續，確定事件仍會觸發且縮圖/進度會即時恢復。
- **預期**：
  - `PendingMediaStore` state 會跟著事件轉換為 `ready / uploading / synced / failed`，不需重新選檔。
  - Upload Center、學生卡片、課程總覽的狀態與進度文字一致，無重複任務或遺失的縮圖。
