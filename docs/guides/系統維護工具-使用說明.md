# 系統維護工具 - 使用說明

## 🎉 更新內容（2025-11-06）

### 已完成功能

#### 1. ✅ 後端自動清理機制
- 讀取學習記錄時自動過濾不存在的檔案
- 自動更新 `photos-meta.json`、`videos-meta.json`、`media-meta.json`

- **回應**: 詳細的統計資訊（掃描數、清理數、刪除數）

#### 3. ✅ 系統維護工具頁面
- **獨立頁面**: `https://calendar.funlearnbar.synology.me/system-maintenance.html`
- **嵌入管理後台**: 已整合至管理後台「系統工具」→「系統維護」
- **功能**:
  - 後端清理無效記錄
  - 前端清除緩存
  - 一鍵完整清理（推薦）

## 📍 使用方式

### 方式 1：管理後台（推薦）

1. 訪問管理後台：
   ```
   https://calendar.funlearnbar.synology.me/admin-dashboard.html
   ```

2. 點擊左側導航：**系統工具** → **系統維護**

3. 選擇清理方式：

   - **前端清除緩存**：清除瀏覽器緩存
   - **一鍵完整清理**：自動執行後端清理 + 前端清除（推薦）

### 方式 2：獨立頁面

直接訪問：
```
https://calendar.funlearnbar.synology.me/system-maintenance.html
```

### 方式 3：測試頁面

用於除錯和測試：
```
https://calendar.funlearnbar.synology.me/test-cleanup.html
```

### 方式 4：API 調用

```bash

curl -X POST https://calendar.funlearnbar.synology.me/api/clean-all-metadata

# 查看健康狀態
curl https://calendar.funlearnbar.synology.me/api/health
```

## 🔧 功能說明

### 1. 後端清理無效記錄

**作用**：
- 掃描 `data/learning-portfolio/` 所有目錄
- 檢查 `photos-meta.json`、`videos-meta.json`、`media-meta.json`
- 移除不存在檔案的記錄
- 刪除空的 meta 檔案

**統計資訊**：
- 掃描目錄數
- 處理目錄數
- 移除照片記錄數
- 移除影片記錄數
- 刪除空檔案數

**何時使用**：
- 刪除照片/影片後
- 發現前端顯示不存在的檔案
- 系統維護時
- 定期清理（建議每月一次）

### 2. 前端清除緩存

**作用**：
- 清除 localStorage
- 清除 sessionStorage
- 清除 Cookies
- 清除 Cache API

**注意事項**：
⚠️ 清除後需要重新登入 LINE LIFF

**何時使用**：
- 前端顯示舊資料
- 照片/影片更新後未顯示
- 系統行為異常

### 3. 一鍵完整清理（推薦）

**作用**：
1. 執行後端清理（自動掃描並清理）
2. 等待清理完成
3. 自動清除前端緩存
4. 自動重新載入頁面

**優點**：
- ✅ 完整解決前端顯示舊資料問題
- ✅ 無需手動操作多個步驟
- ✅ 自動化流程
- ✅ 安全確認機制

## 🎯 使用場景

### 場景 1：刪除照片後仍顯示

**問題**：刪除照片後，前端仍顯示已刪除的照片

**解決方案**：
1. 進入管理後台 → 系統工具 → 系統維護
2. 點擊「一鍵完整清理」
3. 確認操作
4. 等待完成（約 5-10 秒）
5. 頁面自動重新載入

### 場景 2：定期維護

**頻率**：每月一次

**步驟**：
1. 進入管理後台 → 系統工具 → 系統維護
2. 點擊「後端清理無效記錄」
3. 查看統計報告
4. 如有需要，點擊「前端清除緩存」

### 場景 3：系統異常

**症狀**：
- 照片/影片無法正常顯示
- 點擊刪除顯示「檔案不存在」
- 前端行為異常

**解決方案**：
1. 先嘗試「前端清除緩存」
2. 如果問題依然存在，使用「一鍵完整清理」
3. 如果仍無法解決，聯繫技術支援

## 🔍 統計報告說明

### 後端清理統計

```json
{
  "totalDirectories": 45,        // 掃描的總目錄數
  "processedDirectories": 5,     // 包含 meta 檔案的目錄數
  "photosMetaCleaned": 1,        // 清理的 photos-meta.json 檔案數
  "videosMetaCleaned": 0,        // 清理的 videos-meta.json 檔案數
  "totalPhotosRemoved": 21,      // 移除的照片記錄總數
  "totalVideosRemoved": 0,       // 移除的影片記錄總數
  "emptyMetaDeleted": 1,         // 刪除的空 meta 檔案數
  "errors": []                   // 錯誤列表
}
```

### 統計解讀

- **totalDirectories = processedDirectories**：所有目錄都正常
- **totalPhotosRemoved > 0**：有無效照片記錄被清理
- **emptyMetaDeleted > 0**：有空的 meta 檔案被刪除
- **errors.length > 0**：有錯誤發生，需要檢查

## ⚠️ 注意事項

### 清理前

1. **建議時間**：選擇非上課時間執行
2. **通知用戶**：如果多人使用，建議通知所有用戶
3. **備份檢查**：重要資料應定期備份

### 清理時

1. **不要關閉頁面**：等待清理完成
2. **不要重複點擊**：避免重複執行
3. **查看日誌**：留意統計資訊和錯誤訊息

### 清理後

1. **重新登入**：LINE LIFF 需要重新登入
2. **驗證結果**：檢查照片/影片是否正常顯示
3. **記錄統計**：保留統計資訊供日後參考

## 🐛 常見問題

### Q1：清理後仍顯示舊照片

**A**：請確認：
1. 是否已清除前端緩存？
2. 是否已重新載入頁面？
3. 是否使用了強制重新整理（Cmd/Ctrl + Shift + R）？

### Q2：清理時出現錯誤

**A**：可能原因：
1. 伺服器繁忙：稍後再試
2. 權限問題：檢查伺服器日誌
3. 網路問題：檢查網路連線

**解決方案**：
```bash
# 檢查伺服器狀態
curl https://calendar.funlearnbar.synology.me/api/health

# 查看伺服器日誌
docker-compose logs -f --tail=100
```

### Q3：需要多久執行一次清理？

**A**：建議頻率：
- **日常使用**：前端緩存清除不需要定期執行
- **系統維護**：每月執行一次後端清理
- **問題發生**：發現異常時立即執行

### Q4：清理會刪除實際檔案嗎？

**A**：不會！
- ✅ 只清理 JSON 記錄檔案
- ✅ 不會刪除實際的照片/影片檔案
- ✅ 只移除「記錄中存在但檔案不存在」的項目

## 📊 技術細節

### 清理流程

```
1. 掃描目錄
   ↓
2. 檢查 meta 檔案存在
   ↓
3. 讀取 JSON 內容
   ↓
4. 驗證每個記錄的檔案是否存在
   ↓
5. 過濾掉不存在的記錄
   ↓
6. 更新或刪除 meta 檔案
   ↓
7. 回傳統計資訊
```

### API 端點

| 端點 | 方法 | 功能 |
|------|------|------|
| `/api/clean-all-metadata` | POST | 批量清理所有無效記錄 |
| `/api/health` | GET | 健康檢查 |
| `/system-maintenance.html` | GET | 系統維護工具頁面 |
| `/test-cleanup.html` | GET | 測試頁面 |
