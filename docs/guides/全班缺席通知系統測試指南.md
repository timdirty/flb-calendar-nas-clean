## 🎯 完整測試流程

### 步驟 1：設定講師群組 ID

1. 開啟管理後台：
   ```
   http://localhost:3002/admin-dashboard.html
   ```

2. 切換到「**通知設定**」頁面（導航列第 6 個選項）

3. 找到「**講師群組設定**」區塊（在「管理員設定」下方）

4. 在「講師群組 LINE Group ID」欄位輸入：
   ```
   C476ccbb325f1207c0fcfbd2301712e12
   ```

5. 點擊「**設定講師群組**」按鈕

6. 應該看到綠色提示：「✅ 講師群組設定成功」

7. 點擊「**查看當前講師群組**」驗證設定：
   ```
   📋 當前講師群組設定：

   群組名稱：講師群組
   群組 ID：C476ccbb325f1207c0fcfbd2301712e12
   說明：所有講師的群組，接收課程異動通知
   ```

---

### 步驟 2：測試全班缺席通知

#### 2.1 準備測試資料

選擇一個有學生的課程，例如「SPM」課程（目前有 21 位學生）。

#### 2.2 模擬全班請假

1. 切換到「**請假登記**」頁面

2. 選擇日期：例如 `2025-01-15`

3. 選擇課程類型：`SPM`

4. **方法 A - 逐個登記（測試單筆）**：
   - 為每位學生逐一登記請假
   - 當最後一位學生請假後，系統應觸發全班缺席檢查

5. **方法 B - 批次登記（推薦）**：
   - 勾選多個學生
   - 點擊「批次登記請假」
   - 如果全部學生都選了，系統應自動觸發

#### 2.3 觀察通知發送

當偵測到全班缺席時，系統應該：

1. **自動發送通知**到三個目標：
   - 📱 講師個人（若在 `teacher_data.json` 中有設定 userId）
   - 👥 講師群組（剛剛設定的 ID）
   - 🏢 正職群組（notification-config.json 中的 admin.group_id）

2. **Flex Message 內容**：
   ```
   ⚠️ 全班缺席停課通知

   [講師名稱] 講師
   ─────────────
   📖 SPM
   📅 2025-01-15
   ⏰ [課程時間]
   ─────────────
   📊 全班 21 位學生皆已請假或缺席

   💡 建議標記為停課
   ```

3. **顯示停課確認對話框**：
   - 彈出視窗顯示全班缺席資訊
   - 提供「確認標記停課」和「取消」按鈕

#### 2.4 檢查日誌

在瀏覽器控制台（F12）應該看到：
```
🔍 檢查全班缺席狀況: {...}
⚠️ 全班缺席: SPM @ 2025-01-15 (21位學生)
📢 準備發送全班缺席通知...
✅ 全班缺席通知已發送: {...}
```

在伺服器終端應該看到：
```
📢 準備發送全班缺席停課通知: { date: '2025-01-15', courseType: 'SPM', ... }
📤 發送通知給講師個人: TED (Uxxx...)
📤 發送通知給講師群組: C476ccbb325f1207c0fcfbd2301712e12
📤 發送通知給正職群組: C9cd9530405411fdd46de96f4e6cdecb7
✅ 全班缺席通知發送完成: 3/3 成功
```

### 步驟 3：測試恢復上課通知

#### 3.1 取消一位學生的請假

1. 切換到「**請假紀錄**」頁面

2. 找到剛剛登記的請假記錄（`SPM @ 2025-01-15`）

3. 點擊其中一位學生的「❌ 取消」按鈕

4. 確認取消請假

#### 3.2 觀察通知發送

系統應該：

1. **自動檢查出席狀態**
   - 檢測到從「全班缺席」變成「有人出席」

2. **自動發送恢復上課通知**到三個目標：
   - 📱 講師個人
   - 👥 講師群組
   - 🏢 正職群組

3. **Flex Message 內容**：
   ```
   ✅ 課程恢復上課通知

   [講師名稱] 講師
   ─────────────
   📖 SPM
   📅 2025-01-15
   ⏰ [課程時間]
   ─────────────
   👤 [學生姓名] 已取消請假
   📊 目前出席人數：1/21

   ✅ 課程正常進行
   ```

#### 3.3 檢查日誌

在瀏覽器控制台應該看到：
```
✅ 請假已取消，Google Sheets 標記已清除
🔍 準備檢查課程恢復上課狀態...
🔍 檢查課程恢復上課狀態: {...}
✅ 課程恢復上課: SPM @ 2025-01-15 (1/21人出席)
✅ 恢復上課通知已發送: {...}
✅ 已通知講師課程正常進行
```

在伺服器終端應該看到：
```
📢 準備發送課程恢復上課通知: { studentName: 'xxx', ... }
📤 發送通知給講師個人: TED (Uxxx...)
📤 發送通知給講師群組: C476ccbb325f1207c0fcfbd2301712e12
📤 發送通知給正職群組: C9cd9530405411fdd46de96f4e6cdecb7
✅ 恢復上課通知發送完成: 3/3 成功
```

## 🔍 進階測試案例

### 案例 1：講師名稱提取測試

測試不同格式的課程標題：

| 課程標題格式 | 預期提取結果 |
|------------|------------|
| `SPM - TED` | `TED` |
| `TED - SPM` | `TED` |
| `SPM TED老師` | `TED` |
| `TED講師 - SPM` | `TED` |

### 案例 2：找不到講師 userId

如果 `teacher_data.json` 中沒有該講師的 userId：

**預期行為**：
- ⚠️ 日誌顯示：「找不到講師 XXX 的 userId，跳過個人通知」
- ✅ 仍會發送到講師群組和正職群組
- ✅ 系統不會中斷，正常運作

### 案例 3：部分學生缺席（不觸發通知）

登記部分學生請假（不是全班）：

**預期行為**：
- ✅ 請假登記成功
- ❌ 不觸發全班缺席檢查
- ❌ 不發送任何通知

### 案例 4：同時多個課程全班缺席

在同一天為多個課程的所有學生登記請假：

**預期行為**：
- ✅ 只顯示第一個全班缺席的對話框
- ✅ 每個課程都會發送各自的通知
- 📝 日誌記錄所有檢測結果

## 🐛 常見問題排查

### 問題 1：沒有收到 LINE 通知

**可能原因**：
1. LINE Channel Access Token 未設定或過期
2. 群組 ID 錯誤
3. Bot 未加入該群組

**檢查步驟**：
```bash
# 1. 檢查環境變數
cat .env.nas | grep LINE_CHANNEL_ACCESS_TOKEN

# 2. 檢查通知配置
curl http://localhost:3002/api/teacher-group-config | jq .

# 3. 查看伺服器日誌是否有錯誤訊息
# 在 npm run dev 的終端視窗查看
```

### 問題 2：找不到講師名稱

**可能原因**：
- 事件標題格式不符合預期
- 講師名稱包含特殊字元

**解決方法**：
```javascript
// 在瀏覽器控制台測試提取邏輯
const title = "您的課程標題";
const parts = title.split('-').map(p => p.trim());
console.log('提取結果:', parts[parts.length - 1]);
```

### 問題 3：恢復上課通知未觸發

**可能原因**：
- 取消請假時仍然全班缺席（其他學生也請假）
- 後端檢查邏輯出錯

**檢查步驟**：
```bash
# 手動測試 API
curl -X POST http://localhost:3002/api/check-class-absence \
  -H "Content-Type: application/json" \
  -d '{"courseType":"SPM","date":"2025-01-15"}' | jq .

# 檢查 allAbsent 是否為 false
```
