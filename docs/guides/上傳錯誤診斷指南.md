- **HTTP 500**: 伺服器內部錯誤（檢查後端日誌）
- **網路錯誤**: 連線問題或 CORS 設定錯誤
- **解析失敗**: 伺服器回應格式錯誤

## 常見問題與解決方案

### 問題 1: 缺少必要欄位

**錯誤訊息**: `缺少必要欄位: date` 或 `缺少必要欄位: course/period`

**原因**: `buildBaseForm()` 或 `buildRecordOperationMeta()` 函數返回不完整資料

**解決方案**:

1. 檢查 `currentCourse` 物件是否正確設定:
   ```javascript
   console.log('currentCourse:', currentCourse);
   ```

2. 確認必要欄位都存在:
   ```javascript
   console.log('date:', currentCourse.date);
   console.log('course:', currentCourse.courseName);
   console.log('period:', currentCourse.period);
   ```

3. 檢查 `learning-record-upload.js` 中的 `buildBaseForm()` 函數:
   ```javascript
   // line ~10132 in learning-record-upload.js
   function buildBaseForm() {
     var fd = new FormData();
     // ... 檢查這裡的邏輯
   }
   ```

---

### 問題 2: 檔案過大

**錯誤訊息**: `HTTP 413` 或 `檔案過大`

**原因**: 檔案超過 multer 或 nginx 的大小限制

**解決方案**:

1. 檢查 `server.js` 中的 multer 設定:
   ```javascript
   // server.js line ~442
   const upload = multer({
     dest: path.join(__dirname, 'uploads/'),
     limits: {
       fileSize: 500 * 1024 * 1024 // 500MB
     }
   });
   ```

2. 檢查 nginx 設定 (如果使用):
   ```nginx
   client_max_body_size 500M;
   ```

3. 對大檔案使用分片上傳:
   ```javascript
   // 檔案大於 10MB 自動使用分片上傳
   if (file.size > 10 * 1024 * 1024 && window.ChunkedUploader) {
     return uploadOneChunked('image', file, idx);
   }
   ```

---

### 問題 3: 記憶體不足導致崩潰

**現象**: 上傳大量檔案或影片時頁面無回應、崩潰

**原因**: Blob URL 未正確釋放，或同時處理太多檔案

**解決方案**:

1. 使用緊急記憶體清理:
   ```javascript
   // learning-record-upload.js line ~43
   emergencyMemoryCleanup();
   ```

2. 減少並發上傳數量:
   ```javascript
   // learning-record-upload.js line ~10203
   function runWithLimit(taskFns, limit) {
     // limit 預設為 2-3，可以降低
   }
   ```

3. 啟用流式上傳模式（依照計劃檔案實施）

---

### 問題 4: 網路錯誤

**錯誤訊息**: `網路錯誤，請重試` 或 `請求超時`

**原因**: 網路不穩定或伺服器無回應

**解決方案**:

1. 檢查伺服器是否運行:
   ```bash
   curl https://calendar.funlearnbar.synology.me/health
   ```

2. 檢查防火牆/CORS 設定:
   ```javascript
   // server.js CORS 設定
   app.use(cors());
   ```

3. 增加超時時間:
   ```javascript
   // api-client.js 可以加上
   xhr.timeout = 120000; // 120 秒
   ```

---

### 問題 5: JSON 解析失敗

**錯誤訊息**: `上傳回應解析失敗`

**原因**: 伺服器回傳非 JSON 格式內容（可能是 HTML 錯誤頁面）

**解決方案**:

1. 檢查診斷工具的「回應內容」，看實際回傳了什麼

2. 檢查伺服器是否返回錯誤頁面（404, 500 等）

3. 確認 API 端點正確:
   ```
   正確: /api/learning-records/upload
   錯誤: /api/learning-record/upload (少了 s)
   ```

## 手動測試流程

如果自動診斷工具無法定位問題，可以手動測試:

### 1. 測試基本連線

```javascript
// 在 Console 執行
fetch('/health')
  .then(r => r.json())
  .then(data => console.log('✅ 伺服器健康:', data))
  .catch(err => console.error('❌ 連線失敗:', err));
```

### 2. 測試最小 FormData

```javascript
// 在 Console 執行
const fd = new FormData();
fd.append('date', '2025-11-07');
fd.append('course', '測試課程');
fd.append('period', '測試時段');
fd.append('isOverview', 'true');
fd.append('overviewSummary', '測試內容');

fetch('/api/learning-records/upload', {
  method: 'POST',
  body: fd
})
  .then(r => r.json())
  .then(data => console.log('✅ 回應:', data))
  .catch(err => console.error('❌ 錯誤:', err));
```

### 3. 測試小檔案上傳

```javascript
// 使用 <input type="file" id="testFile"> 選擇檔案後執行

fd.append('course', '測試課程');
fd.append('period', '測試時段');
fd.append('isOverview', 'true');
fd.append('overviewPhotos', file);

fetch('/api/learning-records/upload', {
  method: 'POST',
  body: fd

  .then(r => r.json())
  .then(data => console.log('✅ 回應:', data))
```

## 進階除錯

### 使用 Chrome Network Tab

1. 打開 DevTools (F12)
2. 切換到 Network 標籤
3. 勾選「Preserve log」
4. 嘗試上傳
5. 找到 `upload` 請求，查看:
   - **Headers**: 確認請求頭正確
   - **Payload**: 確認 FormData 內容
   - **Preview/Response**: 查看伺服器回應
   - **Timing**: 查看各階段耗時

### 使用 Postman 測試

1. 匯入 `FLB-FastAttendance-API.postman_collection.json`
2. 創建新請求:
   ```
   POST https://calendar.funlearnbar.synology.me/api/learning-records/upload
   
   Body (form-data):
   - date: 2025-11-07
   - course: 測試課程
   - period: 測試時段
   - isOverview: true
   - overviewPhotos: [選擇檔案]
   ```
3. 發送並查看回應
