# Docker 容器權限問題修復

**日期**: 2025-10-29  
**問題**: EACCES: permission denied, open '/app/data/reminders.json'  
**影響**: 提醒排程器無法寫入 reminders.json 等資料檔案  
**狀態**: ✅ 已修復

---

## 問題描述

### 錯誤訊息
```
儲存提醒資料失敗: Error: EACCES: permission denied, open '/app/data/reminders.json'
  errno: -13,
  syscall: 'open',
  code: 'EACCES',
  path: '/app/data/reminders.json'
```

### 根本原因
1. **容器內用戶權限不足**：Node.js 程序以 `nextjs` 用戶運行，但掛載的 `/app/data` 目錄所有者是宿主機用戶
2. **docker-compose.yml 的 command 覆蓋無效**：`chown` 命令在以 `nextjs` 用戶運行時無權限執行
3. **Dockerfile 的 USER 指令限制**：設定 `USER nextjs` 後，所有後續命令都以非 root 用戶運行

---

## 解決方案

### 方案概述
使用 **entrypoint 腳本** + **su-exec** 工具，在容器啟動時：
1. 以 root 身份執行權限修復
2. 使用 `su-exec` 切換到 `nextjs` 用戶運行應用

### 實作細節

#### 1. Dockerfile 修改

**新增依賴**：
```dockerfile
RUN apk add --no-cache curl sudo su-exec
```

**創建 entrypoint 腳本**：
```dockerfile
RUN echo '#!/bin/sh' > /entrypoint.sh && \
    echo 'echo "🔧 修復檔案權限..."' >> /entrypoint.sh && \
    echo 'chown -R nextjs:nodejs /app/data 2>/dev/null || true' >> /entrypoint.sh && \
    echo 'chown -R nextjs:nodejs /app/public 2>/dev/null || true' >> /entrypoint.sh && \
    echo 'chown -R nextjs:nodejs /app/logs 2>/dev/null || true' >> /entrypoint.sh && \
    echo 'chmod -R 777 /app/data 2>/dev/null || true' >> /entrypoint.sh && \
    echo 'chmod -R 755 /app/public 2>/dev/null || true' >> /entrypoint.sh && \
    echo 'chmod -R 755 /app/logs 2>/dev/null || true' >> /entrypoint.sh && \
    echo 'echo "✅ 權限修復完成"' >> /entrypoint.sh && \
    echo 'echo "🚀 以 nextjs 用戶啟動應用..."' >> /entrypoint.sh && \
    echo 'exec su-exec nextjs node server.js' >> /entrypoint.sh && \
    chmod +x /entrypoint.sh
```

**修改啟動命令**：
```dockerfile
# 移除 USER nextjs（在 entrypoint 中切換）
CMD ["/entrypoint.sh"]
```

#### 2. docker-compose.yml 簡化

**移除複雜的 command 覆蓋**：
```yaml
services:
  flb-calendar:
    # ... 其他配置 ...
    # 移除 command 區塊，使用 Dockerfile 的 CMD
```

## 技術說明

### su-exec vs gosu vs sudo
- **su-exec**：Alpine Linux 輕量級工具，專為容器設計
- **gosu**：功能類似但體積較大
- **sudo**：傳統工具，不適合容器環境

選擇 `su-exec` 的理由：
- ✅ 輕量級（~10KB）
- ✅ Alpine 官方倉庫支援
- ✅ 完美的權限降級（不保留不必要的能力）
- ✅ exec 替換進程，不產生父進程

### 權限設定策略
```bash
/app/data      → 777 (完全讀寫，確保跨容器共享)
/app/public    → 755 (讀取執行，保護靜態資源)
/app/logs      → 755 (讀取執行，保護日誌)
```

### 2. 健康檢查加強
```yaml
healthcheck:
  test: |
    curl -f http://localhost:3000/api/health && \
    [ -w /app/data/reminders.json ]
```

### 3. 監控檔案權限
在應用啟動時檢查關鍵檔案權限：
```javascript
function checkFilePermissions() {
    const files = [
        '/app/data/reminders.json',
        '/app/data/student-responses.json'
    ];
    files.forEach(file => {
        try {
            fs.accessSync(file, fs.constants.W_OK);
            console.log(`✅ ${file} 可寫入`);
        } catch (err) {
            console.error(`❌ ${file} 無寫入權限`);
        }
    });
}
```

## 總結

### 問題本質
Docker 容器內的用戶權限與掛載目錄的所有者不匹配

### 解決核心
在容器啟動時以 root 身份修復權限，然後降級到應用用戶運行

### 關鍵技術
`entrypoint.sh` + `su-exec` 組合，確保安全且高效的權限管理

### 維護重點
未來如有新的掛載目錄或檔案，需在 entrypoint.sh 中新增對應的 chown/chmod 命令
