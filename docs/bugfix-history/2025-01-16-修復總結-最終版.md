## 📋 問題描述

學生簽到記錄無法精確定位到正確的 Google Sheets 儲存格，例如：
- 「非非 11401」的簽到被標記到第7行（第一個學生），而不是正確的第14行

---

## 🔍 問題根源（最終確認）

### ❌ 最初的錯誤診斷

最初認為問題是：
1. ~~跨課程索引錯誤~~（部分正確，但不是根本原因）
2. ~~`student_data.json` 順序與 Google Sheets 不一致~~（**錯誤的診斷**）

### ✅ 真正的根本原因

**前端在簽到時對學生列表進行了不必要的二次篩選！**

#### 問題代碼（`main.js:16613`）：
```javascript
// ❌ 錯誤：對已經是該課程的學生列表再次篩選
const courseStudents = window.loadedStudentsData.students.filter(s => s.course === courseType);
studentIndex = courseStudents.findIndex(s => s.name === studentName);
```

#### 為什麼這是錯誤的？

1. **`window.loadedStudentsData.students` 已經是該課程的學生列表**
   - 來自 `loadCourseStudents()` 函數（`main.js:15495`）
   - 該函數專門調用 `/api/students/by-course?course=${course}`
   - API 返回的順序與 Google Sheets 工作表**完全一致** ✅

2. **二次篩選可能改變順序或遺漏學生**
   - 經過臨時學生合併（補課/體驗學生）
   - 某些學生的 `course` 欄位可能被處理過
   - 篩選可能遺漏或改變順序

#### 數據流程圖

```
Google Sheets SPIKE 工作表
  ↓ (按工作表順序)
/api/students/by-course?course=SPIKE
  ↓ (順序正確 ✅)
loadCourseStudents()
  ↓ (合併臨時學生，但保持順序)
window.loadedStudentsData.students
  ↓ ❌ 錯誤：再次篩選
.filter(s => s.course === courseType)
  ↓ (順序可能改變)
studentIndex (錯誤索引)
```

---

## ✅ 解決方案

### 修復1: 移除不必要的二次篩選

**修改檔案**: `public/js/main.js` (行 16601-16626)

**核心修復**:
```javascript
// ✅ 正確：直接使用已載入的學生列表（已經是該課程）
const courseStudents = window.loadedStudentsData.students;
studentIndex = courseStudents.findIndex(s => s.name === studentName);
```

### 修復2: 恢復快速模式

**修改檔案**: `public/js/main.js` (行 16636-16647)

**核心修復**:
```javascript
// ✅ 恢復快速模式（使用正確的學生順序）
if (courseType && studentIndex >= 0) {
    requestBody.courseType = courseType;
    requestBody.studentIndex = studentIndex;
    console.log('🚀 使用快速模式');
}
```

## 🎯 為什麼之前的 Postman 測試是正確的？

**Postman 不傳遞 `courseType` 和 `studentIndex`**，觸發後端 Fallback 模式：

```javascript
// Fallback 模式（fast-attendance.js）
const response = await axios.get(
    `/api/students/by-course?course=${courseType}`
);
const students = response.data.students;  // 順序與 Google Sheets 一致
studentIndex = students.findIndex(s => s.name === studentName);  // 正確索引
```

**前端現在也使用相同的邏輯** ✅
