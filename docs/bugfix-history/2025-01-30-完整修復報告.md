## 📋 問題清單與修復方案

### 1. ✅ 講師篩選按鈕不可點擊

**問題描述**:  
搜尋結果中的講師標籤按鈕無法點擊，點擊沒有反應。

**根本原因**:  
- 講師按鈕的 z-index 不足，被其他元素覆蓋
- 缺少明確的 `pointer-events: auto` 聲明

**修復方案**:  
檔案: `public/css/styles.css`

```css
.search-instructor-summary {
    display: none;
    align-items: center;
    flex-wrap: wrap;
    gap: 6px;
    margin-left: auto;
    position: relative;
    z-index: 100; /* 🔥 確保講師按鈕在上層 */
}

.search-instructor-chip {
    /* ... 其他樣式 ... */
    position: relative; /* 🔥 確保z-index生效 */
    z-index: 101; /* 🔥 確保可點擊 */
}

.search-instructor-chip.search-instructor-btn {
    cursor: pointer !important; /* 🔥 強制顯示指針游標 */
    pointer-events: auto !important; /* 🔥 確保可點擊 */
    border: 1px solid rgba(79, 70, 229, 0.2);
}
```

**測試方法**:
1. 執行搜尋並查看講師標籤
2. 點擊講師標籤按鈕
3. 確認講師篩選正確切換

//     window.switchView('week');

### 3. ✅ 週次選擇按鈕需要按兩次

**問題描述**:  
點擊星期快速導航按鈕（一、二、三...）時，需要點擊兩次才能正確定位到對應的星期課程。

**根本原因**:  
使用 `setInterval` 等待 DOM 渲染的機制不夠穩定，且視圖切換和 DOM 渲染的時序無法保證。

**修復方案**:  
檔案: `public/js/main.js` (行 21374-21423)

改用 **Promise-based** 等待機制：

```javascript
// 🔥 滾動到指定星期的課程卡片（關鍵字搜尋）- 改進版 (Promise-based)
async function scrollToWeekdayCard(weekday) {
    console.log('🔍 搜尋星期:', weekday);
    
    // 🔥 先切換到「本週」視圖
    const needSwitch = currentView !== '本週';
    if (needSwitch) {
        console.log('📅 自動切換到本週視圖');
        currentView = '本週';
        
        // 更新按鈕狀態
        const filterButtons = document.querySelectorAll('.floating-filter-btn, [data-view]');
        filterButtons.forEach(btn => {
            btn.classList.remove('active');
            if (btn.getAttribute('data-filter') === 'week' || btn.getAttribute('data-view') === 'week') {
                btn.classList.add('active');
            }
        });
        
        // 🔥 使用 Promise 等待渲染完成
        await new Promise(resolve => {
            // 🔥 設置渲染完成回調
            const originalCallback = window._renderCompleteCallback;
            window._renderCompleteCallback = () => {
                console.log('✅ 渲染完成,準備搜尋星期');
                if (originalCallback) originalCallback();
                resolve();
            };
            
            // 重新渲染事件
            renderEvents();
            
            // 🔥 備用:如果2秒內沒有回調,強制resolve
            setTimeout(() => {
                console.log('⏰ 渲染超時,強制繼續');
                resolve();
            }, 2000);
        });
        
        // 🔥 額外延遲確保DOM完全穩定
        await new Promise(resolve => setTimeout(resolve, 300));
    } else {
        console.log('✅ 已在本週視圖,直接搜尋');
        // 🔥 短暫延遲確保DOM穩定
        await new Promise(resolve => setTimeout(resolve, 100));
    }
    
    // 執行搜尋
    performWeekdaySearch(weekday);
}
```

刪除舊的 `waitForCardsRendered()` 函數（原本使用 setInterval 的不穩定方式）。

**測試方法**:
1. 選擇一位有課的講師
2. 點擊星期快速導航按鈕（例如「三」）
3. **只點擊一次**
4. 確認頁面自動切換到本週視圖並滾動到星期三的課程
5. 測試其他星期按鈕

### 5. ✅ Toast 訊息阻擋點擊

**問題描述**:  
Toast 提示訊息出現時，無法點擊 Toast 後面的元素（例如按鈕、卡片）。

**根本原因**:  
Toast 元素沒有設置 `pointer-events: none`，導致它會攔截所有點擊事件。

**修復方案**:  
檔案: `public/js/main.js` (行 19634-19665)

在 `showToast()` 函數的樣式中添加：

```javascript
toast.style.cssText = `
    position: fixed !important;
    /* ... 其他樣式 ... */
    pointer-events: none !important;  // 🔥 允許點穿 Toast
`;
```

**測試方法**:
1. 觸發一個 Toast 訊息（例如切換講師）
2. 在 Toast 顯示期間，點擊 Toast 下方的按鈕或卡片
3. 確認可以正常點擊到後面的元素
4. Toast 不應該阻擋任何點擊

## 💡 技術要點

### 1. Z-index 層級管理

確保互動元素的 z-index 足夠高：

- 講師按鈕: `z-index: 101`
- Toast: `z-index: 999999`
- 懸浮選單: `z-index: 1000`

### 2. Pointer Events 策略

- **可點擊元素**: `pointer-events: auto !important`
- **點穿元素** (Toast): `pointer-events: none !important`
- **裝飾元素**: `pointer-events: none`

### 3. Promise-based 異步處理

使用 async/await 替代 setInterval，提供更可靠的時序控制：

```javascript
await new Promise(resolve => {
    window._renderCompleteCallback = () => {
        resolve();
    };
    renderEvents();
    setTimeout(resolve, 2000); // 備用超時
});
```

### 4. 設備特定行為

```javascript
const isDesktop = window.innerWidth > 768;
const isMobile = window.innerWidth <= 480;

if (isDesktop) {
    // 電腦版邏輯
} else if (isMobile) {
    // 手機版邏輯
}
```
