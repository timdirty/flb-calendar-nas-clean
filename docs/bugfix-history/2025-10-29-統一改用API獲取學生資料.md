# 🚀 統一改用 API 獲取學生資料

**日期**: 2025-10-29  
**類型**: 效能優化 + 架構改善  
**影響範圍**: 前端所有學生資料載入邏輯  
**風險等級**: 🟢 低風險（完全向後兼容）

---

## 📋 問題分析

### 原有方式的問題

```javascript
// ❌ 舊方式：直接讀取靜態 JSON 檔案
fetch('/student_data.json')
```

**缺點：**
1. ⚠️ **無快取機制** - 每次都重新讀取檔案
2. ⚠️ **缺少臨時學生** - 體驗課、補課學生需要手動合併
3. ⚠️ **效能較差** - 沒有伺服器端優化
4. ⚠️ **不易擴展** - 未來新增資料源需要修改多處

### 新方式的優勢

```javascript
// ✅ 新方式：使用統一 API
fetch('/api/students')
```

**優點：**
1. ✅ **5分鐘快取** - 響應速度極快（快取命中時 <50ms）
2. ✅ **自動合併臨時學生** - 體驗課、補課學生自動包含
3. ✅ **統一資料來源** - 所有前端統一調用
4. ✅ **支援手動刷新** - `POST /api/students/clear-cache`

✅ **完全兼容** - 新增的 `regularCount` 和 `temporaryCount` 為額外資訊，不影響現有邏輯。

### 快取機制說明

**檔案**: `google-sheets-students.js` 第 12 行

```javascript
this.CACHE_TTL = 5 * 60 * 1000; // 5 分鐘快取
```

**行為：**
- ✅ **首次請求**: 從 `student_data.json` 讀取 (~100ms)
- ✅ **快取命中**: 直接返回記憶體資料 (<10ms)

**手動刷新快取：**
